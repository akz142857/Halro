# Governance summary fact fences and minimal batches

`GET /admin/api/v1/governance/summary` retains its WorkUnit cohort basis, inclusive dates (at most 90 days), requested definition version, at most 100000 eligible units, checked financial sums and completeness rules.

The handler captures one Governance fact prefix before reading the accounting cohort. For each mature unit (closed and without accepted-request or pending-attempt activity), it observes the latest revision for exactly `(project, work unit, definition, version)` at that prefix. Reports arriving later do not replace the selected facts, even when their IDs sort earlier. Missing facts remain unevaluated. Open/inflight units contribute in-progress cost and do not become evaluated solely because an Outcome exists.

The response's Governance watermark identifies this fixed native sequence/offset. The accounting watermark identifies the independent coherent Ledger cohort cut. Neither field claims an atomic transaction across journals. Existing denominators, success values, estimated/unknown cost treatment, overflow behavior and no-eligible/no-success reasons remain unchanged.

The server keeps only counters and a batch of at most 64 mature references; it no longer clones all project/definition Outcomes or constructs a full-history current-value map. Each owner read returns only ordered scoped references, found flags and categorical values. Same-batch duplicate references reuse the same observation. Evidence and revision histories do not cross this boundary.

Each batch allows at most 1 MiB of reference identity bytes, 4 MiB of source bytes and at most 20 revisions per unique reference. The disk adapter meters raw Record JSON before decoding; the resident State adapter guards field sizes before encoding its bounded source-meter copy. A wide batch is split only on the byte-limit error, with the same fence and deadline; no failed batch's values are consumed. A legal single native revision chain fits the bound (`20 × 192 KiB < 4 MiB`), where native Governance payloads are capped at 64 KiB. This is a per-operation work bound, not a claim about query-total work, allocation peaks or shared physical memory fees.

The fence is ephemeral, signed for one Manager's complete native Summary, has no Manager/State pointer and is unusable by another Manager. Every batch checks live ownership and source/projection alignment. Normal writes may proceed between batches; State uses bounded per-definition revision history, and the disk adapter follows immutable Supersedes links to the fixed cut inside one short View. Sequence and offset must place a disk fact on the same side of the selected cut. A malformed/missing chain, bad scope, source/bucket/position error, cancellation or closed owner invalidates the whole batch and prevents a partial HTTP summary. The handler retains the existing two-second context deadline; mutex/native IO waits do not become forcibly interruptible.

This authority authenticates the in-process prefix selection, not persisted content or key sets. The disk backend still requires a fresh exclusive DB rebuilt from the complete authenticated journal. WorkUnit detail now uses [bounded complete revision history](work-unit-outcome-history.md). Default Runtime/Replica State residency, trusted restart, export snapshots, Ledger State cohort scanning, shared budgets and Linux/production capacity acceptance remain pending.
