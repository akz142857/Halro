# Primary unconfirmed append admission

Status: partially implemented in the local source tree; I-03/I-06 remain open. Optional configuration now routes Ledger, Metadata, Audit, Governance and provider-object native writes through Primary admission before source persistence. The fixed 65,536-entry table is charged before recovery; recovered bytes are charged up to the Recovery suffix ceiling, and any excess remains a tracked recovery debt that blocks new appends while bounded peer retransmission continues. Live permits merge into one Primary owner and are released only after the confirmed member state is persisted. This is local implementation evidence, not production acceptance.

## Current source facts

- Each native journal now has a `BeforeDurable` admission hook that receives the fully encoded batch before the first native write. `AfterDurable` receives the same admission after source sync and transfers it to `RecordDurableWithAdmission`; uncertain native writes retain their admission until successful source close. Provider-object writes reserve every bounded chunk before publishing the source file.
- [`PrimaryCoordinator.RecordDurable`](../../internal/replication/primary.go) encodes and appends the authenticated ordering record after the source store callback. The source-backed Primary then reconstructs and sends frames through fixed per-peer windows. Queue acceptance is not durable confirmation, and the window bytes are not a substitute for the accumulated unconfirmed append allowance.
- [`ConfirmationTracker`](../../internal/replication/ack.go) keeps a contiguous registered index and a confirmed watermark. A valid cumulative durable ACK advances the prefix; it does not retain a per-frame acknowledgement map. `PrimaryCoordinator.Acknowledge` persists the confirmed member state before publishing the new confirmation watermark.
- Startup reconstructs the exact unconfirmed suffix from authenticated native sources. The fixed release table is precharged at `32 * 65,536` bytes. If the suffix exceeds configured entry or Recovery-byte limits, startup retains bounded index/byte state, marks replication unavailable, blocks new admissions, and continues peer-window retransmission. ACK progress recharges the remaining suffix before reopening new admissions. A suffix larger than the fixed 65,536-entry table still fails coordinator construction.

## Required ownership contract

1. A new append must acquire its bounded count/byte allowance before any participating native store writes or syncs the corresponding batch. The acquired reservation follows the append through the store's durable callback and is bound to the resulting ordering index; the after-durable callback cannot be the first admission point.
2. The reservation remains charged while that index is in the contiguous unconfirmed suffix. A cumulative durable ACK releases exactly the newly confirmed prefix, and only after the existing member-state confirmation barrier succeeds. Sending, queue drain, Apply-only progress, connection loss, and HTTP success do not release it.
3. Reservations for the five sources—Ledger, Metadata, Audit, Governance, and provider objects—share the Primary's Manager and one fixed aggregate owner. They must not create a history-sized map of budget permits. Per-index release accounting must be bounded by the configured in-flight limit and use the authenticated ordering prefix as its authority.
4. If native persistence succeeds but ordering publication or confirmation-state publication becomes uncertain, retain the relevant reservation under a fail-closed recovery owner; do not refund it because the caller received an error. Restart reconstructs the exact suffix and acquires Recovery ownership before publishing readiness.
5. If the new limit is below the recovered suffix, preserve the source facts, keep readiness closed, and continue bounded retransmission. Track the bounded recovery debt separately from the bytes charged against the configured cap; do not admit new appends until the remaining suffix fits and is fully charged. A suffix larger than the fixed hard entry bound fails closed.

## Focused acceptance evidence

- Focused tests prove pre-write callback order and transfer for each native source. Budget refusal tests for Ledger, Metadata, Audit and Governance prove the authenticated head and file length stay unchanged; provider-object refusal proves the source directory is not published.
- Local fault-injection tests cover native write/sync uncertainty for all four journals, ordering-journal sync failure, and confirmed-state persistence failure during ACK. Admissions remain charged until source/coordinator shutdown release. A focused confirmed-state persistence failure test now reopens the ordering journal and proves the unconfirmed suffix is charged to Recovery before it can be confirmed; equivalent restart/rejoin proof for every fault stage remains open.
- The synthetic ACK test proves the confirmed prefix releases its admitted bytes once; replayed cumulative ACKs do not release twice. A two-peer recovery test gives both peers independent windows for the same suffix and releases their cumulative ACKs concurrently; confirmed state publishes once and the shared Recovery charge retires once. An authenticated TLS/net.Pipe test exercises the actual PeerSession record framing in both directions: both peers receive the recovered frame, send cumulative ACKs over TLS, and retire the Recovery charge with one confirmed-state publication. The ConnectionManager/SessionRegistry replacement test separately holds a new generation before preparation, accepts another peer's ACK, then drains the replacement; only the confirmed prefix is refunded, the old generation never sends through the new session, and disconnect does not release the remaining suffix. A single test combining live TLS traffic with session replacement remains open.
- Startup tests prove an over-limit suffix remains nonready, is retransmitted one frame at a time through the bounded peer window, rejects new appends, and reopens only after ACK progress clears the debt and restores full charging. Suffixes beyond the fixed table bound remain rejected.
- Optional Primary metrics expose configured/used unconfirmed byte limits, bounded entry usage, recovery debt/over-limit state, admission refusals and last durable confirmed-prefix progress without identity labels. The existing confirmed-index metric remains authoritative.

These are repository-level gates only. They do not replace target Linux capacity calibration or production acceptance.
