# Governance export file streaming

The four normalized schema-1 datasets (`work_units`, `runs`, `outcomes`, `outcome_definitions`) and version-1 manifest retain their fields, independent accounting/Governance watermarks, row counts, sequence ranges and SHA-256 checksums. WorkUnit/Run rows omit additive committed/reserved accounting amounts. Dataset ordering remains producer ordering; the manifest's four entries are sorted by dataset name.

`WriteExportStream` accepts typed producers which yield borrowed rows synchronously, stop on errors, and return only after their work finishes. Producers must retain the relevant owner/fixed-prefix authority, fetch bounded pages, and release State locks/DB transactions before yielding; the sink does not provide those guarantees for them. Nil producers mean empty datasets. `WriteExport` is a compatibility wrapper that iterates supplied slices without making new dataset copies. Its callers still retain those slices.

The sink encodes only one row at a time and writes through a 64 KiB buffer while computing SHA-256 over the same written bytes. It does not marshal a whole JSON array, split it into RawMessages or read the whole output file back. Field sizes and domain-bounded arrays are guarded before Marshal; encoded rows are checked afterward. WorkUnit/Run/Outcome rows allow 1 MiB; definitions allow the metadata journal's 8 MiB ceiling, preserving native legal wide creator metadata. The manifest allows 64 KiB. Worst-case escaping can expand the definition's guarded fields to roughly 48 MiB before the encoded-row check rejects it; encoder growth, return copies and JSON pools mean this is not a bound on physical peak memory. Shared fees and production calibration remain pending.

The export exclusively claims a new directory and never overwrites an existing one, even an empty directory. Before claiming it, the parent and every ancestor are synced from the bottom up, including existing directories left by failed first-run attempts. Dataset files are flushed/synced and renamed; their directory entries are synced before manifest creation. The temporary manifest is synced, renamed last, then export and parent directories are synced before success. `manifest.json` is the commit marker. Orderly failures clean only this call's owned directory and return a zero manifest; a crash may leave an incomplete directory without a manifest, which must not be consumed.

Yield calls are serialized; encoding/write/context errors are latched even if a producer ignores them. Finishing joins entered callbacks, seals the sink and clears its buffer/context/encoder dependencies. Late callbacks fail before IO. Sources remain responsible for finite concurrency and must not retain callbacks. Context cancellation prevents publication before the commit stage; file IO and producer code are not forcibly interruptible. Once publication starts, durability barriers complete without treating cancellation as permission to skip them.

`VerifyExportContext` reads a bounded manifest, requires exactly the expected four unique datasets and safe filenames, then streams bounded NDJSON lines and hashes the same open descriptors. It checks object JSON, actual count/ranges, nonzero Outcome sequences not exceeding the declared Governance head, checksums, and regular-file identity/size/mtime at completion. The manifest descriptor remains open and is rechecked after all datasets. `VerifyExport` uses a background context for compatibility. Checksums and file identity checks establish consistency, not native journal authentication, complete key sets, proof of absence or an atomic cut across journals.

The public Runtime handler now uses selected disk owners and fixed paginated Gov/Ledger/Metadata sources. Its default State compatibility branch still retains a complete Ledger snapshot and WorkUnit join map, while Gov/Metadata use finite sources. Only the explicit unsupported Ledger backend error selects that branch; disk failure does not reuse Runtime State aliases. Shared RAM/disk fees, default owner migration, trusted recovery, Linux/RSS/cgroup acceptance, power-loss/SIGKILL and ENOSPC coverage remain required; this does not close I-10 or make the default export path bounded.

A disk-only [fixed accounting export cut](accounting-export-cut.md) supplies finite lifecycle/maturity pages. `BeforePublish` now runs once after all datasets and the temporary manifest have been synced, before the final manifest rename; its error or context cancellation prevents publication and cleans owned output. The [fixed Governance source and bounded owner join](governance-export-owners.md) require source `Complete` here, while the accounting ticket remains held through publication. The [global Metadata prefix](metadata-definition-export.md) supplies the third finite source through a callback covering publication. Runtime permits one active export without a waiter queue, permanently withdraws new admission on drain and joins the accepted callback, audit and response before closing resources. Governance [Manager retirement](governance-manager-lifetime.md) now joins the complete source/publication callback and releases its own dependencies. These are operation/lifetime limits, not physical fee or IO-duration guarantees. Public integration evidence is in [handler verification](../verification/performance/2026-10-03-governance-export-handler/README.md); full default owner migration, Metadata general retirement and shared fees remain pending.
