# Shared logical disk budget

Latest Doctor/provider/seed/read-only Audit ownership and verification boundaries:
[maintenance consumers](../verification/performance/2026-10-06-memory-bounded-resume/maintenance-consumers.zh-CN.md).

`resource_budget` now accepts `total_disk_bytes` and per-class disk limits for Configuration, Active, Cache, IO, Background, Completion and Recovery. The shared `resourcebudget.Manager` already applies `Cost.Disk` to the same atomic claim, owner-retain and release paths as RAM. Configuration now maps those limits into that manager. No product default is set; absent or zero disk limits remain closed to disk claims.

`recovery_reserve_disk_bytes` is removed from the normal pool. The Recovery class ceiling must fit within that reserve; Recovery owners can use it even while ordinary admission is pressured. HTTP new-work admission atomically reserves configured Completion RAM and disk credits with its Active RAM envelope and holds both through handler return, including synchronous finalization. Deferred workers reserve the same Completion credit with their Background RAM before reading persisted input, and keep it through their terminal write; refusal leaves the accepted record queued. HTTP refusal happens before reading the request body. These are logical lifetime credits, not physical block reservations or per-ledger-record byte reconciliation; other asynchronous or persistent state needs its own owner. The completion ceilings must fit normal shared capacity alongside persistent disk owners. Class ceilings can overlap; the global total remains a shared ceiling.

Disk bytes are logical accounting. They do not reserve filesystem blocks, include uncharged owners, reconcile actual file sizes on their own or guarantee writes against ENOSPC. The Runtime `resource_pressure` sampler separately stops normal work using the lower free-byte and inode headroom across the data-directory and system temporary-directory filesystems; an unavailable reading from either filesystem fails closed. Backup creation adds a one-shot headroom check for its selected output filesystem before building the snapshot, using the same configured disk/inode stop lines. That preflight does not reserve blocks or prevent later ENOSPC. Both physical thresholds and logical capacity must be measured on the target profile before enabling these settings. Unknown/stale pressure fails closed for normal work; do not set guessed values.

`ledger_projection_disk_bytes` and `usage_projection_disk_bytes` optionally enable bbolt data-file ceilings for the default Standalone/Primary/Replica fresh Ledger and Usage projections. `governance_projection_disk_bytes` does the same for the default Standalone/Primary fresh Governance Outcome projection; Replica continues to use its authenticated native Governance journal.

Each positive projection ceiling also charges its complete file bytes plus 32 MiB of mapping/freelist RAM in the same claim, separately from the reducer workspace. Admission precedes candidate IO; the claim moves Recovery→Background only after authentication and is released after actual reader/DB close and captured-inode deletion. Failed or foreign-inode retirement retains the whole claim. Configuration aggregates all three mappings with Metadata mapping RAM in Recovery/reserve, Background and normal shared capacity, including concurrent request/deferred/capture work; HA aggregates them too. These conservative fees remain estimates requiring physical target calibration. Zero still leaves that mapping unmetered.

`ledger_segment_index_disk_bytes` optionally caps the authenticated `segments.idx` ordinal sidecar and its bounded rebuild workspace. The sidecar is keyed from the Ledger chain key and bound to the exact `segments.json` bytes; it is a rebuildable lookup cache, while the JSON manifest remains authoritative. A missing, stale, or damaged sidecar is rebuilt by streaming the manifest, and Roll replaces it only after the manifest publication step. Standalone assigns the ceiling to its Ledger Log; HA divides it into six bounded shares for the current sidecar, a pinned predecessor, up to three NativeSource reader locators, and publication workspace. Runtime acquires one Recovery Disk claim before constructing them and reclassifies it to Background after startup. The claim survives Runtime.Close when the sidecar remains on disk; if no persistent sidecar was created, it releases after Log and reader close. Roll rejects a next generation before publishing intent when the configured ceiling would be exceeded. This is logical accounting, not a physical block reservation; remaining CLI/one-shot owner integration and target capacity acceptance remain open.

`governance_log_disk_bytes`, `audit_log_disk_bytes`, and `metadata_journal_disk_bytes` optionally cap the native authenticated Governance, Audit, and Metadata journals in Standalone, Primary, and Replica. Runtime startup charges each configured ceiling to Recovery before opening/attaching the journal, rejects an existing file over the ceiling, and moves the claim to Background after authenticated attach (Replica also applies its confirmed prefix first). Local append and replicated frame batches are preflighted as a whole before writing. Metadata safe-prefix trimming carries its ceiling across candidate publication and reopen; if an eligible slow HA member prevents the cut from advancing, new writes fail closed at the ceiling. The claims remain for the Runtime lifetime because closing Runtime does not delete these journals.

`metadata_store_disk_bytes` separately caps the Metadata bbolt data file. Standalone/Primary/Replica Runtime acquires one shared Recovery claim for its full Disk ceiling **and ceiling + 32 MiB of logical mapping/freelist RAM** before file/KMS key-slot inspection. Exact-role opens enforce bbolt `MaxSize` and actual-FD existing size; the same claim moves to Background after authenticated journal reconciliation (Replica after confirmed application). Actual Store close joins native users before Runtime retires the RAM part; Disk and its persistent claim overhead remain because the file survives. Key Slots inspection borrows this exact live claim and rejects a substituted path, policy, budget or Manager. Configuration checks startup Recovery, normal RAM alongside pricing/request work, and Background alongside deferred/capture work. The estimate is conservative admission, not a physical RSS guarantee.

With `memory_state_required`, a positive `legacy_metadata_file_disk_bytes` sets a separate ceiling for every actual legacy bbolt unlock/maintenance file and materialized backup or key-rotation image. It must not exceed `metadata_store_disk_bytes`. Configuration and real mapping owners charge this smaller **enforced file ceiling + 32 MiB**; selected Metadata COW/root owners retain the full `metadata_store_disk_bytes` reservation. Existing files and staged exports that exceed the legacy ceiling fail closed. Zero preserves the original mapping estimate, and the option is refused for the legacy engine. This separates two physical consumers without granting uncharged mappings or shrinking the COW reserve.

Configured one-shot App commands preserve one root resource context for Metadata, Audit, Ledger index and Usage archive consumers. Each open Metadata handle reserves its own mapping RAM before IO and releases it only after actual bbolt close; whole-file snapshots and compaction destinations acquire separate file ceilings before data copying. Compaction uses finite 8 MiB destination write transactions and a separate destination mapping fee. A fixed eight-slot source/stage table conservatively retains a full file ceiling and bounded path-owner RAM per distinct path throughout the job, including closed/failed/removed scratch; a ninth path is refused. This table is not a durable inode inventory or permission to remove replacements. Native journal buffers, all old crash leftovers, block reservation, physical publication/rollback peaks still need their own accounting. Commit failure after native durability permanently withdraws Store reads/writes and Runtime readiness/traffic; a fresh owner authenticates and replays the retained native fact. Zero disables this ceiling and does not make the default configuration physically bounded.

Budgeted offline backup creation and staged restore acquire private Ledger, Usage and Governance reference-job RAM/Disk before native readers or scratch directories are created. Ledger and Usage require positive projection ceilings and the accounting workspace; Governance requires its positive projection ceiling plus a 32 MiB workspace. Mapping fees conservatively include each complete file ceiling. References use commit-time file limits, actual close, captured-inode discard and empty-directory removal; any retirement failure keeps the entire job fee and rejects success. Unknown entries or replacements are preserved. Legacy pricing compatibility inspection reserves a separate raw read-only Metadata mapping, rejects wide decoded rows/deep nested buckets and preserves historical hash order.

Usage full archive verification uses a private authenticated disk radix index with fixed-depth lookups rather than a historical bbolt freelist/mapping. Its explicit decoder workspace reserves FileBytes + 32 MiB of shared RAM before scratch IO; the default is 288 MiB, a conservative logical admission cost rather than an RSS claim. A date comparison holds the same RAM fee across resumable steps until actual scratch close/deletion. Enlarging the admitted limits recreates the reference session and reacquires its fees. The complete IndexBytes + FileBytes disk reservation also has to fit both the archive tree and shared class ceilings. Small archives do not bypass these reservations; insufficient configured capacity is a deterministic refusal. Exact owned-file/empty-directory cleanup replaces recursive scratch deletion.

`ordering_journal_disk_bytes` caps the non-trimmable authenticated HA Ordering journal on Primary and Replica. Runtime startup reserves its complete configured ceiling before authenticated open, rejects an existing file over the ceiling, then retains the claim as Background after the journal is authenticated (Replica publishes it only after applying its confirmed prefix). Each ordering record is rejected before writing if it would cross the ceiling, so a rejection preserves the authenticated head. Once full, HA writes stop. An operator may raise the configured ceiling and restart after checking the shared envelopes, or perform a safe new-incarnation migration; deleting or trimming ordering history in place is not supported. The journal remains on disk after Runtime.Close, so its claim is retained for the Runtime lifetime.

App maintenance, backup, promotion, and seed paths receive the configured native journal ceilings; offline `halro ledger seal`, file-key initialization, KMS initialization, backup creation/restore, and EstablishMemberState seed validation now acquire a command-scoped Recovery claim for the configured Ledger segment-index ceiling before opening the Log/NativeSource and release it after the native owner closes. Backup create/restore reuse one command Manager for Ledger and Usage archive claims so concurrent ceilings are aggregated; complete native inventory and physical acceptance remain open. Usage archive maintenance, verification, backup and Doctor run under their data-directory lock and use a command-scoped Manager: it charges the tree ceiling to Recovery before inventory and charges temporary archive work to the same Recovery pool through cleanup. Runtime-backed archive work uses the Runtime Manager and the configured IO class after startup. Enabling the archive ceiling requires positive `io_disk_bytes`; each operation is still refused if its actual bounded reservation does not fit the class or shared remaining capacity. Projection claims remain until their captured inode is actually removed. All enabled ceilings must fit together within Total, Background, startup Recovery, and Recovery reserve limits, with dedicated Recovery claims per persistent owner and normal claim slots for every owner after Recovery handoff; when Usage archive budgeting is enabled, configuration also reserves transient Recovery/IO claim slots and fixed control RAM. HA validation reserves fixed control cost for its claims. Zero leaves the corresponding path unmetered.

The three projections use bbolt `Options.MaxSize`, which refuses page allocation/file growth at the configured data-file size; `Tx.Size()` inside an update callback is only the transaction's starting high-water mark and is not a commit-time growth guard. Journal and projection ceilings are logical file/data-file limits, not physical block reservations; they do not bound mmap/page cache, filesystem metadata, trim candidates, or uncharged files. `usage_archive_disk_bytes` optionally caps the complete `UsagePath` tree. Runtime reserves the full ceiling from Recovery before bounded inventory, rejects unknown or oversized trees, validates the archive and selected role, then retains the same claim as a Background owner because the archive survives Runtime.Close. Archive writers enforce the ceiling before each write. One-shot maintenance, verification, backup and Doctor hold a command-scoped Recovery owner while their data-directory lock is held; their transient reservations use the same Manager and release after exporter close. The shared disk limit remains logical: physical free-space pressure and ENOSPC need separate target evidence. Other backup trees and remaining persistence owners still need their own claims and physical capacity evidence before production values are enabled.

`backup_workspace_disk_bytes` caps each temporary bbolt SourceCatalog, archive observation/declaration/extraction index and report spool when the command uses a resource budget. Each simultaneously live file independently claims its full ceiling plus ceiling + 32 MiB RAM from the same command Recovery Manager before file creation; bbolt `MaxSize` or the spool writer enforces the file ceiling. Verification/report/Restore requires a positive ceiling in budget mode. A pinned verified handle retains the original Manager and cancellation even when Extract receives a context without values; a different explicit budget is refused. `backup verify --config` selects this configured scope. The no-config compatibility API remains unmetered. The limit does not include staged snapshots, the encrypted archive output, or physical block reservation; the independent selected-output filesystem preflight remains a point-in-time check.

A positive SourceCatalog ceiling also holds ceiling + 32 MiB mapping RAM in that Recovery claim, with separate startup/reserve capacity validation. Private projection references now hold each file ceiling + 32 MiB alongside their reducer workspace: a two-DB Usage reference owns accounting workspace + both file ceilings + 64 MiB. Actual reader/engine Close and exact own-inode unlink precede refund. A missing original name cannot prove retirement because the inode may have been renamed; successful repeated retirement requires this receipt's earlier successful unlink. Actual cleanup errors retain these complete fees. Complete staging-tree ownership and physical capacity acceptance remain open.

`restore_workspace_disk_bytes` optionally caps the authenticated payload bytes extracted into restore staging. After the full archive verification pass, Restore reads the verified byte total from its operation-owned inventory; it rejects oversized input before staging, or charges the exact payload total to Recovery through staging cleanup. This bounds logical extracted file bytes, not filesystem metadata or physical blocks; the staging-filesystem preflight remains a separate point-in-time check.

`usage_archive_read_ram_bytes` optionally charges each active Usage archive reader to the shared IO RAM envelope; the fixed four reader slots are checked together with one request and pricing IO during configuration validation. Startup and one-shot readers use Recovery, while Runtime readers use IO. The permit follows the read through actual file close and releases on refusal or exit. Zero leaves this shared per-reader RAM accounting disabled. This is a configured logical envelope, not allocator or RSS measurement.

`halro_resource_budget_disk_bytes` reports current logical charges; `halro_resource_budget_class_disk_bytes` gives their fixed-class breakdown. `halro_resource_pressure_disk_available_bytes` reports the Runtime sampler's lower physical free-space value across the data and system temporary filesystems, with the matching lower inode count. One-shot backup output preflight is operation-scoped and is not included in this Runtime metric. Neither metric is a physical reservation.
