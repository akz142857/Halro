# Usage archive disk budget contract

Status: the opt-in package ceiling is wired to the default Runtime/app configuration. Runtime reserves the full archive ceiling from shared Recovery before inventory and retains it as a Background owner after archive validation and role selection. Pre-write tree admission covers regular `ExportDisk*`, legacy `Export(Snapshot)`/`PruneBefore`, catalog migration/build/root publication, date-state and date-policy publication, retained-date verification indexes, verification/reclaim scratch, and date-file/page reclaim writers. Runtime-backed shared transient reservations now cover `ExportDisk*`, snapshot export/prune, archive verification, archive-catalog migration, date-catalog activation/build, date-file reclaim spools, and long-lived date verification/reference/orphan-page scratch owners, including the no-disk-owner Runtime exporter fallback. Configuration requires a positive `io_disk_bytes` envelope when the archive ceiling is enabled; an operation still fails closed if its reservation exceeds current class/shared capacity. One-shot app maintenance, verification, backup and Doctor use a command-scoped Manager under their data-directory lock; lower-level direct package APIs still require callers to provide an owner when shared accounting is required. The full failure matrix, Linux capacity acceptance and production acceptance remain open.

## Current source facts

The Runtime's selected Usage exporter lives under `cfg.UsagePath()`. The normal disk-backed export path is `Exporter.ExportDiskStep` in `internal/usage/disk_export.go`, called from Runtime maintenance. Its `DiskExportLimits` bound one operation (`WriteBytes` and `WorkBytes`), but do not cap all retained archive data across operations. Exporter startup validates catalog format/schema and some paged-catalog structure; when the archive ceiling is enabled, bounded startup inventory includes every regular file under the locked Usage tree, including crash leftovers. The optional `usage_archive_read_ram_bytes` setting charges each of the four fixed archive-reader slots to Recovery during startup/one-shot work and IO during Runtime work; zero leaves the shared reader RAM charge disabled.

The directory can contain published Parquet/NDJSON partitions, legacy or paged manifests, catalog pages, date-retention policy and proof state, interrupted build/reclaim state, retryable partition orphans, and scratch files. Retention and orphan deletion have separate date/native authority, owner identity, publication, and Close/join rules. A disk ceiling must preserve those rules.

## Required behavior

1. Add an opt-in configured logical ceiling for the complete persistent Usage archive tree. The accounting identity is the locked `UsagePath` tree, not only manifest-referenced partition bytes. It includes catalog and policy files, unreferenced retryable files, and crash leftovers. Symlinks, non-regular files, path replacement, unreadable entries, and arithmetic overflow fail closed. Enumeration uses bounded memory and context/deadline checks.
2. During Runtime startup, reserve the configured full ceiling from shared Recovery before archive inventory or validation. Reject startup if the actual tree exceeds it or cannot be inventoried. After the exporter has validated the current root and assumed its runtime role, reclassify the same claim to Background and retain it for the Runtime lifetime because the archive survives Runtime.Close. Standalone and Primary may publish; Replica remains read-only. Maintenance/CLI paths enforce the configured file ceiling even when they do not own a live Runtime Manager claim.
3. Before an export, catalog build, verification spool, date-reclaim candidate, or other operation creates disk state, reserve its maximum transient coexistence cost in the shared IO/Recovery class. The owner covers every actual write through file close, rename/directory barriers, cleanup, and joined callbacks. A cancelled caller cannot return the claim while native IO or cleanup is still active. If the profile has no calibrated transient envelope, the operation is refused when shared-budget enforcement is enabled.
4. Before publishing each file or root, preflight the current tree plus the operation's maximum additional bytes against the configured ceiling. Every write path must use the same tree owner and enforce the limit before bytes can cause the tree to cross it; checking only after close is too late for a hard ceiling. Candidate files and catalog pages count while they coexist with the previous root. Failed publication preserves the previous usable root and leaves only bounded, inventoried retryable orphans.
5. Reaching the ceiling refuses the new publication and preserves authoritative Ledger facts and the prior archive root. It never triggers implicit retention, date pruning, or deletion of files whose owner is unknown. An explicit, authorized retention operation may reclaim only the prefix its existing native/date policy permits, after verifying ownership and joining physical unlink/close.
6. Runtime readiness, error metrics, and operator diagnostics distinguish a full logical archive ceiling from physical free-space pressure and from corrupt/unknown inventory. The logical ceiling does not reserve blocks or replace statfs/ENOSPC handling.

## Acceptance evidence

- Startup accepts an exact-cap tree, rejects cap+1 and an uninventoryable tree before readiness, and proves no mutation on rejection.
- Actual output, staged root/catalog, date-build/reclaim state, Parquet column buffers, and retryable orphan coexistence cannot cross the configured tree ceiling. Tests cover exact boundary, short writes, cancellation during blocked IO, rename/fsync failures, restart, and a failed retirement that retains the owner until true join.
- Shared Manager snapshots show Recovery before validation, Background for the persistent Runtime owner afterward, a separate bounded transient owner during disk work, and no early refund after cancellation. Runtime.Close joins exporter work and retains the at-rest charge.
- Standalone and Primary Runtime paths, explicit authorized retention, backup/restore, and one-shot maintenance/CLI opens preserve existing roots, date authority, role prefixes, and ownership rules.
- Local tests and race/vet cover the affected packages. A target-Linux capacity run separately validates physical co-existence, scratch peaks, filesystem limits, and ENOSPC behavior; that run is not implied by unit or Runtime tests.

The `Options.ArchiveDiskBytes` implementation inventories the complete tree and charges bytes before writes; verification reserves the configured maximum simultaneous index and partition-spool sizes before creating scratch. The per-operation budget conservatively counts bytes even if a temporary file is later removed. The default Runtime exposes `resource_budget.usage_archive_disk_bytes`, claims the full ceiling from Recovery before inventory, and retains the claim in Background after archive validation/role selection. Runtime-backed export, prune and archive verification reserve from startup Recovery or runtime IO and release only after operation cleanup joins. Snapshot export and catalog migration reserve their bounded tree/work envelope; date-catalog build, activation and policy writes reserve their bounded call scratch; date-file reclaim holds the configured file spool bound. Date comparison, reference and orphan-page indexes retain a shared reservation for the entire scratch-owner lifetime and release after close/removal. One-shot app maintenance, verification, backup and Doctor use a command-scoped Manager under exclusive data-directory access and release the tree claim after exporter Close. ## Shared comparison RAM and exact scratch retirement

When shared resource budgeting is enabled, Runtime, backup, verify and Doctor pass a comparison-workspace reservation even if the archive file and reader ceilings are zero. Full verification reserves FileBytes + 32 MiB RAM before scratch creation; date verification retains that RAM across finite steps until actual index close, captured-inode unlink and empty-directory removal. With default limits this is a 288 MiB logical fee, not a calibrated RSS guarantee. A request that cannot fit the shared Recovery/IO class is refused before scratch IO; zero file ceilings do not bypass comparison RAM admission.

Full verification now reuses the private MAC-protected disk radix comparison index used by retained-date verification. It stores schema and canonical-row digests, detects duplicate EventID/sequence/path membership and authenticates lookups/absence. It has fixed-depth lookups and no history-sized bbolt mapping, freelist or row cache; saved scratch is never trusted across reopen. File/schema/content correspondence and final frozen native/root checks remain required.

Comparison cleanup removes only captured index/spool inodes and an empty captured directory. Unknown entries, renamed originals or replaced paths reject cleanup and keep the job fees outstanding. A failure in any late fee retirement returns zero report and clears tentative window proof, so cleanup cannot leave deletion authority behind. Resumable date comparison restarts and reacquires fees before increasing a previously admitted RAM/disk ceiling.
