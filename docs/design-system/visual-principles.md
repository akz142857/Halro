# Halro 管理控制台视觉原则

状态：Visual System v0.1（2026-09-17）。本目录是持续规范；一次性审计证据位于 `docs/review/260917-visual-system/`。

## 原则

1. **任务先于装饰**：首屏先给状态、风险与下一步操作，不用超大标题或多层容器制造“高级感”。
2. **层级来自关系**：页面标题、区块标题、对象身份、事实值、标签依次降级；不以随机字号、粗细或颜色代替结构。
3. **清晰胜过密度**：默认保持单一可靠密度。桌面可紧凑，但窄屏交互目标不小于 44px，正文不小于 12px。
4. **颜色只作辅助证据**：成功、警告、危险、未知必须同时有文本、图标或边界；Light/Dark 语义等价。
5. **渐进披露复杂度**：常用判断和主操作直接可见；技术详情、JSON、次要事实进入 disclosure、drawer 或 detail pane。
6. **适配内容而非设备名**：布局按内容失效点切换。320px 到宽屏都能完成主任务，局部数据表可滚动但页面不能横向溢出。
7. **平台习惯优先**：系统字体、清晰焦点、键盘顺序、可取消对话框、减少动画与高对比兼容遵循 Apple HIG 的清晰、层次和一致性方向。
8. **运营真实性优先**：partial、stale、unknown、read-only 与 destructive 状态必须准确，不因视觉简化而被隐藏。

## 反例

- 用 42–46px 营销标题挤压操作台首屏。
- 把 11 个目的地放进无提示的横向滑动条。
- 用原生 `window.confirm` 绕过主题、焦点与文案契约。
- 页面自行新增颜色、断点或 10/11px 字体。
- 把错误只放在会消失的 Toast，或仅靠红/绿表达结果。
- 为窄屏简单缩小桌面表格，而不重排身份、事实与操作。

## 内容原则

- 标题用任务或对象命名，描述说明范围与后果；按钮使用动词。
- 中文与英文表达同一语义，不要求字符长度一致；布局必须容纳英文扩张。
- ID、端点、模型名和代码使用等宽字体，允许换行或局部滚动，并提供既有复制操作。
- 成功反馈可短暂；错误、拒绝和恢复步骤必须持久并靠近发生位置。
