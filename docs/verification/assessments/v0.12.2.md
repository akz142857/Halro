## Range review and defect triage

The range is one production fix plus its merge. Review covered the Admin API,
store transaction and shared/exclusive gate ordering, offline CLI, durable audit
outbox, clock pairing, optional pin evidence and console recovery lifecycle.
No unresolved blocking finding was confirmed.

- Recovery accepts only a clock quarantine and binds its revision, reason and
  currently effective immutable price. A stale/future/expired review, changed
  price, missing/deleted deployment or other quarantine type is refused.
- The exclusive pricing gate spans the durable high-water reset and in-memory
  anchor reset. The high-water update and audit intent commit atomically;
  pending audit delivery drains through the existing outbox after restart.
- Offline recovery requires a stopped Standalone instance, exclusive data-dir
  ownership and the configured Master Key. It opens no listeners or provider
  workers and never resets MFA or edits historical prices, pins or bills.
- A forward observation gap can continue only for the exact prior valid immutable
  `free` price, whose components are all zero and which has no scheduled tiers.
  Existing quarantines, metered prices, version transitions and rollbacks retain
  their guards. The optional diagnostic never becomes a billing input.
- The console requires an explicit review and identity confirmation, clears the
  acknowledgement on refresh and prevents read-only writes. Server checks remain
  decisive for stale reviews and MFA.
- No new unresolved TODO/FIXME marker was introduced. The open bug-label query
  returned none. Existing timing-sensitive Deadman CI issue #487 is accepted as
  a non-blocking, unchanged test concern; no production failure is established.

## Invariants and design

1. Single writer/data directory: preserved; offline recovery holds the exclusive
   directory lock and refuses an active instance or cluster configuration.
2. Ledger authority: preserved; recovery changes pricing trust state and an audit
   intent, not reservations, settlement, existing pins, prices or balances.
3. Fail closed: role/CSRF/MFA, stale price/review and unsafe clock cases refuse;
   the zero-cost exception is explicitly restricted and validated.
4. Secrets: no credentials in clock-gap logs, audit payloads or durable pins;
   password/MFA stay transient. Browser artifact secret scanning is required.
5. Replay determinism: gap diagnostics are captured in the pin; no clock gap is
   regenerated as a billing fact during replay.
6. Bounded retry/fallback: unchanged; recovery and stale-review refresh are
   explicit operator actions, not automatic provider retries or write replay.
7. Capability filtering: unchanged.
8. Compatibility: model API wire behavior and manifests are unchanged. The two
   new Admin routes are included in the frozen Admin route contract.
9. Configuration: unchanged; v0.12.2 default snapshot is byte-identical to v0.12.1.

No parallel legacy implementation or new schema/WAL epoch was added. Optional
JSON fields remain absent for ordinary pins and default to zero when reading old
pins. The new audit action is an operator-visible recovery event. No architectural
rule changed that requires a new ADR; the recovery runbook defines the boundary.

Re-initialisation required from v0.12.1: **no**. Keep a consistent pre-recovery
backup and separately stored Master Key. Older binaries may refuse an undelivered
new recovery audit intent; rollback across recovery should restore that backup,
not assume every partially completed recovery state is backward compatible.
