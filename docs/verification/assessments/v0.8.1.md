The range fixes portable stream finalization accounting, bounds failure-capture
payloads before asynchronous queue ownership, persists the exact Provider
primitive through attempt accounting and recovery, adds actionable accounting
alerts, improves CLI help and Workbench Go examples, and repairs intermediate
desktop-width Admin layouts. It also strengthens fresh-test, web-bundle and
release preflight contracts.

This touches the request path, budget/Ledger attribution, failure capture,
Provider profile contracts, frontend sources and release automation. It
therefore triggers the full Go/frontend gate, race and fuzz evidence, request
path performance comparison, populated recovery/rollback exercise, container
and supply-chain verification, and exact-SHA ordinary CI.

## Defect and review disposition

- Portable Responses and Messages facade completion now occurs before request
  success finalization; a failed terminal emit records `provider_error` without
  retrying a completed Provider attempt.
- Failure-capture JSON is truncated before entering the bounded asynchronous
  queue and again, idempotently, at the storage boundary.
- Reservation, start, settlement and recovery carry the concrete Provider
  primitive; the Ledger rejects primitive/profile mismatches and settlement
  attribution changes.
- Prometheus rules cover shutdown-truncated attempts and stale Accounting
  Leases, with firing/non-firing/resolved rule tests and runbook entries.
- Independent profile/primitive and adapter-construction guards prevent the
  production registry from proving its own mappings.
- No active P0/P1/P2 remained after the ordered remediation and adversarial
  re-review. Remaining external evidence gaps are recorded as unverified rather
  than converted into pass claims.

## Invariants and upgrade impact

The single-writer/data-directory boundary is unchanged. The Ledger remains the
accounting authority; reservation precedes Provider I/O, attempt cost keeps its
real settlement, and ambiguous outcomes remain conservative. New validation
fails closed. No new credential, prompt or response logging path is introduced.
Retries and fallback remain bounded, and no fallback occurs after bytes reach a
client. Provider existence, capability and primitive evidence remain separate.

The new Ledger JSON field is optional for authenticated historical events;
fresh reservations and starts require it, while recovery can settle older
pre-field reservations without inventing attribution. No metadata, checkpoint,
Parquet, frame or backup version changes in this range require re-initializing
the v0.8.0 data directory. Rollback to v0.8.0 retains the usual requirement to
use a verified backup when an older binary refuses newer durable state.
