## Invariants and upgrade impact

1. One process owns each data directory. Import runs inside the owning runtime.
2. The ledger remains the accounting authority. Transfer carries current
   effective prices, while ledger, usage, reservations and settlements stay local.
3. Export requires an administrator. Import validates a fresh target, the
   current preview and step-up material before writing. Deployments and routes
   start disabled. A post-commit replica confirmation failure is reported as
   committed locally.
4. Export DTOs exclude credentials and key material. Import plaintext appears
   once, only on confirmed success. Custom redaction strings and endpoint paths
   can carry sensitive content and the console discloses that export scope.
5. Transfer writes generated IDs, new key hashes and audit intents in existing
   record formats. Replay does not regenerate key material.
6. The request retry and fallback paths are unchanged.
7. Imports revalidate target credentials and preserve explicit Project model
   allowances. Operator declarations require explicit acknowledgement.
8. The published model API compatibility manifest is unchanged. Transfer adds
   three Admin endpoints with their own versioned bundle contract.
9. Instance configuration keys and defaults are unchanged.

Re-initialisation is unnecessary for v0.13.0. There is no new schema rollback
fence. The rollback smoke covered the previous binary after upgrade and normal
traffic. Keep the verified pre-upgrade backup for recovery, including when
new import operations have taken place.

## Evidence boundaries

release claim. There is no new request hot-path performance claim.
