## 2 Performance

- Benchmarks, HEAD vs v0.2.0 built from the same tree and run on the same
  host back-to-back (Apple M4 Pro, `-benchtime=1s`): **no regression in the
  range.** Route resolution 4.5µs/41 allocs vs 4.5µs/41 allocs; strict
  redaction 70.4µs/32 allocs vs 70.6µs/32 allocs; rolling redaction 15.8µs/79
  allocs (improved vs the baseline doc); Token Guard fixed 163ns vs 161ns,
  EWMA 176ns vs 178ns; WAL replay 60.5 MB/s vs 59.6 MB/s with byte-identical
  allocation (230.77 MB, 3.000M allocs both sides).
- Finding (non-blocking, pre-existing): `performance-baseline.md` (2026-07-31)
  is stale for route resolution — 405ns/1 alloc there vs ~4.5µs/41 allocs at
  both v0.2.0 and HEAD. The drift landed before v0.2.0 (capability-aware
  routing era) and already shipped; it is not a v0.3.0 change. The baseline
  document should be re-measured and re-dated so the next assessment compares
  against reality.
- Serialization scan of the range: **no new locks or funnels on the request
  path.** New mutexes are admin-only (elevation grants) and SIGHUP-only
  (reload state); the TLS handshake path is one atomic load + map lookup,
  deliberately lock-free; unmatched-SNI logging is throttled with atomics.
- Web bundle: v0.2.0 1168 KB → HEAD 1216 KB total (+4.1%), while the entry
  graph now excludes all 11 page chunks (per-path lazy loading) — first paint
  loads less than before. Delta explained.
- `stress` job: judged on the release run when the tag is pushed.

## 3 Invariants (each: untouched, or touched and why it holds)

1. Single-writer / single data dir — untouched; restore preserves the
   pre-restore dir for rollback rather than writing over it.
2. Ledger WAL authority — untouched (no `internal/ledger` change); real chain
   authenticates; settlement paths not in range.
3. Fail-closed — touched, holds: strict config decode refuses unknown keys
   with line numbers; TLS material loads before any listener binds (a bad
   keypair is a refusal to start, not a plaintext listener); certificate
   reload replaces the bundle only when every source loaded; metrics endpoint
   refuses unauthenticated scrapes; elevation window absent/zero/negative all
   answer "prove it again".
4. No secrets in logs/errors/metrics/audit — touched, holds: reload warns with
   section *names*, never values; certificate descriptions carry name (from
   the certificate, not SNI), expiry, and a public-material fingerprint — no
   key bytes; safelog wrapper retained; step-up audit records outcome only.
5. Determinism on replay — improved: detection reuse now judged on the
   caller's clock (`CreateModelCapabilityDetection(..., now)`).
6. Bounded retry/fallback — untouched.
7. Capability filtering rejects, never drops — touched, holds: the two new
   Mantle profiles declare their unsupported fields in the manifests; ceiling
   == defaults, nothing widened; portable requests carrying unsupported
   members are routed away before Provider I/O.
8. Compatibility manifests — `docs/compatibility/endpoint-manifests.json`
   updated in the same range for all five Mantle profiles and locked by the
   golden test.
9. Config semantics — `elevation_window` is a pointer: absent → 10m default,
   explicit 0s → ask every time, negative → clamped to 0; defaults present in
   `default.yaml` + `config.example.yaml`; bilingual reference metadata gate
   answered.

## 4 Design

- Fix-in-place: clean. Signatures changed in place (`logging.Open`,
  `CreateModelCapabilityDetection`); no V2 constructs. The two new Mantle
  profile IDs name a real distinction (route × wire shape) rather than
  duplicating a wrong one; the two existing IDs that changed route did it via
  profile Revision 1→2, the mechanism built for exactly this.
- Format versions: no durable schema change (bbolt stays v30; elevation grants
  are memory-only by design); config incompatibility surfaces as a strict
  refusal, not a misread.
- One-way doors accepted knowingly: profile IDs `bedrock.mantle.chat.v1` /
  `bedrock.mantle.responses.v1`; config keys
  `admin.model_capability_detection.elevation_window`, `tls.certificates[]`;
  metric names `halro_reload_total`, `halro_reload_last_success_timestamp_seconds`,
  `halro_tls_certificate_expiry_seconds` (bounded labels, conventions kept);
  reload item strings. All read deliberate and consistently spelled.
- ADRs: none added in range. The reload membership rule ("a reload replaces
  material, never semantics") is an architectural rule currently recorded only
  as a comment block in `reload.go`; consider promoting to an ADR. Non-blocking.
- Threat surface: no new endpoints beyond additive admin status fields; no new
  outbound network paths; SIGHUP is a local signal answered only after startup
  completes.
