committed web bundle from the lockfile. Initial gzip is 255,338 → 258,827 bytes
(+1.37%). Workflow schema lint and the release contract/evidence tests passed,

and usage verification. The schema 42 archive also worked with candidate
restore and with a separate restore using the original v0.14.0 binary.

## Performance comparison

Paired v0.14.0 and candidate samples on Apple M4/macOS 27.3 used Go 1.26.11,
`GOMAXPROCS=4` and six samples with 200 ms minimum per case. A second,
interleaved 500 ms pass rechecked route resolution and redaction after the
first pass showed slower timings.

| Benchmark | v0.14.0 → candidate |
| --- | --- |
| Request lifecycle | 5.873 → 4.945 ms/op geometric mean. Allocations rose 3.59% (164.4 → 170.3 geom.) on the existing allocating path. |
| Deployment price pin | 5.207 → 5.002 ms/op geometric mean. The 1- and 64-worker changes were inconclusive, with the 8-worker case 8.72% faster. |
| Replay 100,000 WAL records | 683.4 → 599.0 ms/op median (p=0.093). |
| Route resolution, interleaved | 5.398 → 5.369 µs/op (p=0.699); 41 allocations on both, with 1.09 KiB/op more allocated bytes after pricing data expanded the routing target. |
| Strict and streaming redaction, interleaved | 76.31 → 74.96 µs/op (p=0.394) and 17.28 → 18.94 µs/op (+9.57%, p=0.004), respectively. Streaming redaction timings were noisy and its source was unchanged. Allocation counts were unchanged. |
| Token Guard and Project admission | No statistically significant slowdown; allocation counts unchanged. |

The request path continues to use the existing Ledger writer. The append
timing fix records completion before delivering results on the existing
channel and adds no new goroutine or I/O to that path.

## Invariants and upgrade impact

1. The data-dir lock still fences one writer. Migration 43 waits for pending
   metadata journal replay before publishing the schema and backfilled prices.
2. WAL reservations still precede Provider work. Added dimensions travel with
   pinned pricing and historical settlements retain the recorded charge.
3. Auth and capability gates remain explicit. An apply cannot report successful
   Project access when the live snapshot is stale or the alias is disabled.
4. Config transfer excludes secrets and ledger/audit data. The only new plaintext
   output is a newly issued Gateway Key in the authenticated handoff.
5. Replay uses persisted pricing and usage; migration backfills both write rates
   from each stored input rate. The new Ledger timing uses runtime observations.
6. Retry and fallback policy is unchanged.
7. Capability enforcement is unchanged; lifetime dimensions map reported usage
   without fabricating a split when totals disagree.
8. The generated facade manifest records the additive optional response fields.
   Both Anthropic version values remain accepted by the runtime.
9. Config defaults and example are unchanged. Schema 43 applies to stored
   metadata, and portable configuration has its own explicit version 2.

Standalone needs no reinitialization. An older binary needs a verified
pre-upgrade backup restored into a separate or empty data directory. HA uses
offline backup, restore into a new incarnation and Replica reseed. The local
binary smoke covered standalone file-mode key custody. Existing WAL frame
encoding is unchanged; metadata schema 43 and portable bundle v2 fence the
changed storage and interchange contracts.
