through the v0.8.2 release commit on `main`.

## Recommendation

**GO for a full v0.8.2 publication, subject to green ordinary CI and the formal
dry-run and publishing release gates on the exact release commit.** This release
may advance GitHub Releases, GHCR, Homebrew and APT only through the existing
single release workflow and its downstream acceptance chain.

No active known P0/P1/P2 defect remains in the reviewed range. One upgrade
blocker was found during release review: v0.8.1 wrote
`providers.bedrock.region` into `config.yaml`, while the first v0.8.2 candidate
removed the decoding field under strict YAML validation. That would have
prevented an existing installation from starting. The candidate now retains a
validated compatibility-only decoder and carries an upgrade regression test.

## Scope and triggered passes

The release adds Admin-managed Provider egress through HTTP CONNECT, including
encrypted optional Basic Auth, direct-versus-proxy trust-boundary selection,
private-address and cleartext acknowledgements, hot runtime snapshots, safe
failure classification, backup coverage, doctor checks and schema-38 persistence.
It also establishes and applies the Admin visual system, responsive navigation,
resource layouts, theme tokens and automated visual-system ratchets.

The range touches outbound networking, credentials, Vault-encrypted records,
Provider adapter construction, configuration compatibility, bbolt migration,
backup/restore, Admin APIs and frontend sources. It therefore triggers the full
Go and frontend gates, the full race suite, migration and backup tests, transport
failure tests, release workflow contract tests, container and supply-chain gates,
and exact-SHA ordinary CI. Real Provider calls remain opt-in and were not run.

## Defect and review disposition

- Provider proxy selection is explicit per Provider. A configured proxy failure
  never retries the same Provider directly; routing to a different direct
  Provider remains an independently configured Route decision.
- CONNECT destinations use validated Provider literal addresses while Provider
  TLS continues to authenticate the original hostname. Proxy endpoints and
  optional credentials are separately validated, with credentials kept in the
  Vault and excluded from API responses and diagnostics.
- Proxy mutations produce immutable runtime snapshots so existing streams can
  drain on their old transport while new attempts use the new definition.
- Metadata migration 38 creates the managed proxy bucket and fences schema-37
  readers without rewriting existing Provider JSON. A v0.8.1 binary therefore
  refuses the upgraded directory instead of ignoring a proxy binding and serving
  it directly.
- Existing `providers.bedrock.region` YAML is accepted, trimmed and validated so
  a v0.8.1 installation can start v0.8.2 without first editing its configuration.
  The value is compatibility-only; saved Admin-managed Credentials and Provider
  endpoints remain authoritative.
- Provider and outbound-proxy rows were restructured after browser review to
  prevent overlap and action loss, while preserving keyboard names, confirmation
  gates and narrow-screen access.

## Invariants and upgrade impact

The single-writer and data-directory boundaries are unchanged. The Ledger remains
the accounting authority, reservation still precedes Provider I/O, fallback stays
bounded, and no fallback occurs after bytes reach a client. No new prompt or
response logging path is introduced. Proxy diagnostics are bounded metadata and
exclude endpoints, reason phrases, usernames, passwords and Credential IDs.

Upgrade from v0.8.1 does not require pre-editing `config.yaml`; the retired
Bedrock region block may be removed after the saved Bedrock Credential endpoint
is verified. Re-initialization is not required. A complete pre-upgrade backup is
required, and rollback to v0.8.1 requires restoring it because metadata schema 38
is deliberately unreadable to schema-37 binaries.
