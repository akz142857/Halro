## Defect and review disposition

The complete range was reviewed as one change, including `api.ts`, `App.tsx`,
`Login.tsx`, notifications, localization, CSS and regression tests. No unresolved
blocking finding was confirmed.

- Only confirmed Admin-session 401 responses enter recovery. Incorrect
  passwords, MFA/step-up, permissions, network failures and forwarded Gateway
  authentication responses retain their own contexts.
- Concurrent expiry responses coalesce. Protected query/mutation caches,
  notifications and CSRF are cleared; new protected requests pause until sign-in
  succeeds. An in-flight server operation is not rolled back or replayed.
- Session generations prevent delayed old failures and snapshots from expiring a
  newer session or replacing its CSRF. Password and MFA completion resume the
  same destination, subject to each destination's existing URL normalization.
- Unsaved form values are discarded when protected views unmount; recovery copy
  states this. The update notes preserve this operator-visible boundary.
- The issue query returned no open issues labelled `bug`. No new unresolved
  fix marker was found in the reviewed source diff.

## Invariants and design

1. Single writer/data directory: unchanged. Smoke processes stop before another
   binary opens the isolated data directory.
2. Ledger authority: unchanged. Browser cache clearing does not alter server
   reservation, settlement or accounting.
3. Fail closed: confirmed expiry removes protected views and pauses new protected
   calls. Other failures do not masquerade as successful authentication.
4. Secrets: no new logging or persisted browser credentials. Protected caches,
   notifications and CSRF are cleared; the artifact scan passed.
5. Replay determinism: unchanged; no durable clock/randomness changes.
6. Bounded retry/fallback: server behavior unchanged. Failed mutations are never
   automatically replayed; existing query retry limits remain bounded.
7. Capability filtering: unchanged.
8. Compatibility manifests and server endpoints: unchanged.
9. Configuration: no new keys or meanings. v0.12.1's snapshot equals v0.12.0.

No parallel legacy implementation, new durable epoch or irreversible server API
was introduced. The shared recovery interaction is documented in
`docs/design-system/patterns.md`; no server architectural rule changed that
requires a new ADR.

Re-initialisation required from v0.12.0: **no**. No new durable-format rollback
fence. Keep a backup and a separately stored Master Key; synthetic smoke does
not certify every live deployment state.

**Formal publication is authorized after the required gates pass.** Merge this
preparation only after successful PR CI, then require ordinary push CI for the
exact merged commit and a successful `release.yml` rehearsal (`version=v0.12.1`,

claim is made. HA remains experimental and unsupported in production. All formal
archive architectures, package reproducibility, signatures and downstream clean
installs belong to the exact-version release and channel workflows.
