## Defect and review disposition

The review of `e6cb9bae` covered shared interactions/authentication, AI
integration and page/copy/style changes as one range. The
[review record](../../review/261104-console-simplification/post-commit-review.zh-CN.md)
documents four P2 findings, all fixed:

- C12-01: ordinary forms could submit while factor enrollment was unknown or
  failed. Shared readiness now guards every applicable button and handler;
  pending, failure, stale error, retry and enabled-factor cases pass.
- C12-02: JavaScript object literals lost JSON Schema `__proto__` properties.
  Generated requests parse safely encoded JSON text in both stream modes.
- C12-03: Go examples silently truncated successful responses at 1 MiB.
  Success now copies the full response to stdout with checked errors and
  bounded working memory; error diagnostics retain the 1 MiB limit.
- C12-04: usage empty states implied no lifetime history despite the default
  console-window query. The empty state and default selector now identify
  that window, with custom-range guidance and filter-reset coverage.

C12-02/03 were inherited by the extracted generator; C12-01/04 were regressions
in the console changes. No open issues labelled `bug` were returned during
preparation. No unresolved new fix marker was introduced.

   verification, backup, restore or binary switching.
2. Ledger authority: server reservation/settlement unchanged. Browser labels
   are not an accounting or lifetime-history authority.
3. Fail closed: unknown/error enrollment blocks incomplete client submits;
   server factor/password and authorization checks are unchanged.

   project metadata. Environment references and existing in-memory/redaction
   boundaries remain; artifact scan passed.
5. Replay determinism: no new replay clock, randomness or format.
6. Retry/fallback: server policy unchanged. Generated Go success output copies
   bytes without whole-response buffering, checks read errors and caps error
   diagnostics. No new retry loop.

   upstream capability evidence; instructions preserve that distinction.
8. Compatibility manifests: no facade wire contract changed. Existing manifests
   remain valid; examples share the reviewed workbench request body.
9. Configuration: no new keys or semantics. The v0.12.0 historical snapshot is
   exactly the v0.11.0 default configuration.

Re-initialisation required from v0.11.0: **no**. No new durable-format rollback
fence. Keep a pre-upgrade backup and separately stored Master Key; this rollback
fixture does not promise every possible deployment state.
