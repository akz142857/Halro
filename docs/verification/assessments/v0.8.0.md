# v0.8.0 pre-release assessment

Date: 2026-09-11
Range reviewed: `v0.7.1` (`84f2638e973f23935b9eda423143f65ff25a852c`)
through the v0.8.0 release commit on `main`.
Assessor and owner: ziy

## Recommendation

**GO for v0.8.0 publication, subject to a green ordinary CI run and release dry
run on the exact release commit.** The owner explicitly requested publication
on 2026-09-11 after the comprehensive review and remediation results were
reported. The formal workflow must use the same `main` commit as the dry run and
must not start if `main` moves between those runs.

The owner accepts that no billable real-account BigModel, MiniMax or Kimi smoke,
real AWS KMS/CloudTrail exercise, production alert-receiver test, 24-hour soak,
or complete browser/assistive-technology matrix was run. This accepts an
evidence limitation, not a known P0/P1 defect; local fake-provider, fake-KMS,
upgrade, backup/restore, security-canary and browser-component coverage remains
the available evidence.

## Scope and triggered passes

The range adds encrypted failed-request diagnostics, Provider Offering/Surface/
Region identity, regional BigModel / Z.AI profiles and Coding Plan support,
standardized Provider failure attribution, and three-language SDK dependency
updates. Remediation also changes metadata/checkpoint compatibility boundaries,
Ledger settlement validation, failure-capture concurrency, Admin console flows,
and the release supply chain.

This triggers every v0.x deep pass: full Go/frontend and generated-bundle gates,
request-path security and performance review, Provider compatibility review,
populated upgrade/rollback and backup/restore, dependency/license/vulnerability
checks, containers, SBOMs, signatures, provenance and an exact-SHA release dry
run.

## Defect, security and review disposition

- The source-wide review found 17 confirmed findings: five P1, ten P2 and two
  P3. F-001 through F-017 are fixed and regression-tested in the release tree.
- Candidates C-002 through C-007 are closed. C-001 remains an explicit product
  fact: MiniMax Global General and Subscription use the same observable
  host/path/auth shape. Halro requires separate Offering/Surface-bound
  acknowledgement and labels the identity `operator_declared_unverified`
  instead of claiming mechanical verification.
- Metadata schema 37 and Usage checkpoint 14 fence v0.7.1 rollback before
  listeners bind and force derivative reconstruction from the authenticated
  Ledger. Runtime construction also rejects unsupported Parquet manifests.
- Pending-lease recovery preserves frozen Provider attribution, and the Ledger
  append boundary rejects settlement attribution changes and inconsistent
  outcome/phase/class/status semantics.
- A real static authorizer canary echoed by a local fake upstream was absent from
  decrypted capture, read-only Admin payload, HTTP error, logs, audit and disk.
  Capture stores no arbitrary upstream prose and uses one bounded worker.
- Restricted policy acknowledgement is durable on both Credential and Provider;
  missing or stale revisions are withheld before adapter construction and can be
  re-confirmed through the console.
- BigModel reasoning policy is keyed by exact Profile and model. Explicit `none`
  is represented as disabled where supported, and incompatible or unknown
  effort is rejected before Provider I/O.

The remediated tree passed `go test -count=1 ./...`, `go vet ./...`, focused
failure-capture/gateway/budget race tests, all 44 frontend Vitest files (604
tests), TypeScript checking, production build, browser-artifact secret scan,
and a second byte-identical bundle rebuild. Release/archive/run-evidence

The ordinary CI and release dry run named in the recommendation are deliberately

commit containing this assessment. The release workflow itself re-runs the full
quality, race, SDK, stress, frontend, vulnerability, container, packaging,
signature and provenance graph before it may create a tag.

## Upgrade and rollback

Existing v0.7.1 data upgrades in place; re-initialization is not required.
Metadata schema 36 advances atomically to 37, clears the derivative Usage
checkpoint and rebuilds version 14 from the authenticated Ledger. Parquet schema
6 partitions remain readable while new manifests/rows use schema 8.

After v0.8.0 first opens the directory, v0.7.1 refuses schema 37 before serving.
Rollback therefore means restoring the verified pre-upgrade v0.7.1 backup, not
reusing the upgraded directory. Existing restricted-product records have no
invented consent: they remain stored but are withheld until the operator accepts
the current policy revision for both the Credential and Provider connection.

## Performance and invariants

Same-host Apple M4 Pro / Go 1.26.6 comparisons found registry resolution +5.4%,
100,000-record Ledger open/replay +0.3%, and request-lifecycle medians between
-3.8% and +4.5%; no time regression crossed the 10% investigation threshold.
The reviewed frontend graph grew 1.30% from 220,942 to 223,815 gzip bytes.

The single-writer/data-directory boundary remains intact. Ledger is still the
only accounting authority; reservation precedes Provider I/O and ambiguous
results remain conservatively settled. New startup, policy and format checks
fail closed. Provider prose and credentials do not enter logs, metrics, audit or
Admin errors. Replay uses frozen attribution, retries/fallbacks stay bounded,
unsupported capability shapes are rejected rather than dropped, and stable
Profile/Surface/Offering identifiers have independent literal compatibility
gates. No second routing authority or unbounded queue was introduced.

## Design and supply chain

The change fixes existing constructs in place and introduces no parallel V2
model. Durable semantic changes advance their machine-readable version boundary.
Offering kind remains descriptive and does not decide routing, authentication,
pricing, retry or budget behavior. Model existence and capability evidence
remain separate.

The release job requires successful ordinary CI for its exact main commit,
builds amd64/arm64 binary archives, Debian packages and gateway/dead-man
containers, scans both container products, generates source/binary/image SPDX
SBOMs, signs blobs, verifies attestations, creates the annotated tag only after
all gates pass, publishes multi-architecture GHCR manifests and `latest`, then
dispatches the exact version and commit to Homebrew and APT repositories.

dry run at the exact commit used by the formal release workflow. Re-initialization

real-provider smoke, real KMS/CloudTrail, production alert receiver, 24-hour soak
and full assistive-technology matrix: **not run; residual evidence boundary
