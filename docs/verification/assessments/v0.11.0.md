## Defect and review disposition

The release range includes the provider/dependency changes merged in #471-#482.
The #482 multi-role review identified seven concrete issues; all were fixed in
`ea1e744a` with regression coverage, and exact-head PR CI plus merged-main CI
passed. The aggregate range was re-read for cross-profile reasoning boundaries,
redaction, tool replay, price readiness, capability evidence and upgrade impact.
No remaining release-blocking finding was identified; this is not a claim of
an independent second review of every dependency's source.

The preparation's final bounds review found that initial Responses item
snapshots were retained without sharing the cumulative delta budget, and that
initial tool arguments could bypass the 32 KiB check before deferral. Both
regression tests failed before the fix and passed afterward; the complete
OpenAI adapter package also passed. Initial snapshots now consume the stream
budget and initial arguments obey the same bound as later deltas. This changes
no durable format or concurrent lifecycle.

The repository's open `bug`-labelled issue query returned no issues on
2026-11-04. No new unresolved implementation marker was found in the changed request paths.
Known remaining interfaces and account-specific limitations are recorded in
[the API review matrix](../provider-api-review-2026-11.md),
[the OpenAI runbook](../../runbooks/openai-api-compatibility.md), and
[the Ark runbook](../../runbooks/volcengine-ark.md). In particular, provider
executed streaming tools, stored-item references and several newer native
provider interfaces remain unsupported; unknown model IDs receive no inferred
capability evidence. Separate cache-write price tiers remain outside the ledger
pricing schema. No capability is claimed from those gaps.

## Invariants and upgrade impact

1. Single writer/data directory: unchanged; smoke stages stopped the owning binary before verification, backup, restore and version changes.
2. Ledger authority: unchanged settlement/reservation protocol; new usage tiers remain subsets rather than extra totals. All six real-binary stages matched Ledger/usage exactly.
3. Fail closed: unsupported fields, model-specific semantics and version/payload combinations are rejected before provider I/O. Missing/disabled deployment records do not bypass pricing quarantine.
4. Secret handling: visible summaries remain redacted and absent from the opaque envelope; upstream errors do not expose bodies/credentials. Browser artifact secret scanning passed.
5. Replay determinism: no new accounting replay randomness or wall-clock dependency. Reasoning ciphertext and original item IDs/tool association survive stateless replay.
6. Bounded retry/fallback: existing retry limits retained. Truncated/malformed Responses streams remain ambiguous; no fallback after partial output. Deferred tool arguments reuse bounded per-item buffers and are emitted in bounded UTF-8-safe fragments.
7. Capability filtering: reviewed exact model identifiers only; list enumeration is distinct from capability evidence, and unsupported sampling/effort/output controls are rejected rather than silently dropped.
8. Compatibility manifests: updated for affected facades/profiles; fixtures match and official SDK contracts pass. Existing OpenAI Chat connections are not automatically redirected to Responses.
9. Configuration: default configuration bytes are unchanged from v0.10.1 and snapshotted as v0.11.0. No new migration or retired-key rule is introduced.

Re-initialisation required from v0.10.1: **no**. No durable-format rollback fence
was introduced. Rollback was observed on the test fixture above; it does not
promise old builds understand newly created Ark/Responses deployment settings.
