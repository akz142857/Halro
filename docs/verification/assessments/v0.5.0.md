## 1 Defects

- **Full gate: pass.** `make check` exit 0 — fmt, `go test ./...`,
  `go test -race ./...`, `go vet`, frontend vitest, observability config.
  `git diff --exit-code -- internal/webui/dist` clean after a fresh
  `make frontend`, both before and after the release version bump.
- **Range review**: eight independent roles over `v0.4.0..HEAD` as one diff
  (rollup accounting, summary query, security/egress, migration, bug hunt, API
  compatibility, registration architecture, frontend), then five adversarial
  verifiers over the most severe findings.
- **Adversarial verification changed the result again**, as in the 260805 and
  260807 rounds: of the five most severe findings, **none stood as originally
  written**. One had its accounting half removed and its blast radius widened
  from one profile to five; one had its central inference overturned (acting on
  it as filed would have violated the capability-ceiling invariant); one was
  reproduced but reclassified from persistent mis-accounting to a transient read
  that self-heals; one had its trigger condition refuted by an existing
  measurement; one split three ways.
- **Blocking findings: 1, fixed before this record was signed.**
  `halro backup create` refused a data directory written by v0.4.0, having
  already migrated its schema past what the v0.4.0 binary opens — leaving a
  directory no binary could archive, at the moment an operator most needs a
  backup. Root cause: the backup path treated a stale-but-legitimate usage
  checkpoint payload as corruption, while the startup path treats the same bytes
  as "rebuild from the Ledger". Fixed in place so both paths answer the same
  question the same way; regression test
  `TestBackupSucceedsWhenTheStoredUsageCheckpointPredatesThisBuild`, verified in
  reverse (defect restored, test fails with the exact message measured on the
  real binary, `-count=1`).
- **Logged, non-blocking: 16.** Listed in `docs/review/260901/progress.md`
  (P2–P17). The two worth naming here:
  - A portable `/v1/messages` request carrying any `output_config.effort` and
    routed to `minimax.chat.v1` fails after the budget reservation, with no
    fallback, while the published endpoint manifest declares that translation
    supported. The same shape of gap — a request the field rules admit and the
    renderer then refuses — affects five profiles via `reasoning_effort: "max"`.
  - `profileOperationTable`'s operation→primitive values have no guard anywhere
    in the tree, and `docs/contracts/adding-a-platform.md` names a guard for them
    that four reverse experiments showed does not cover them.
- **Real-provider smoke**: not re-run. MiniMax was measured against a real
  international account on 2026-08-31/09-01 (#250); that evidence was reviewed.
  It is Beta and gates nothing. **The Responses profile and the mainland host
  `api.minimaxi.com` are recorded as not measured**, and
  `provider-real-matrix.md` notes those runs carried no `-commit` binding and
  produced no archived evidence file.

- **Sampled benchmarks, HEAD against v0.4.0 back to back on one host** — not
  against the published table, which is stale (below):

  |---|---|---|---|

  | `BenchmarkReplayLargeWAL` (×3) | 505.2–506.6 ms/op | 507.5–518.1 ms/op | no regression (HEAD marginally faster) |

- **Bundle delta: +3.15%** (1,267,421 bytes vs 1,228,753 at v0.4.0), under the
  10% threshold; it carries a new summary panel, route grouping and i18n.
- **Flagged: `docs/verification/performance-baseline.md` is stale and must not be
  used as a regression judgement.** It records route resolution at 405 ns/op with
  one allocation; **both** v0.4.0 and HEAD measure ~5,050 ns/op with 41
  allocations on this host today. The drift predates v0.4.0 and was noted in the
  260827 round; measuring both sides confirms it is not this range. Re-measure it
  or annotate the commit it describes, or the next round will report a
  ten-month-old drift as a new regression.

## 3 Invariants

1. **Single-writer, single data directory** — untouched. The offline rebuild
   command holds the exclusive data-directory lock; the rollup has exactly one
   writer.
2. **Ledger WAL is the accounting authority** — held, and exercised: every
   upgrade path in this release converges on "clear the derivative and replay
   the WAL". Verified end to end on a real v0.4.0 directory.
3. **Fail-closed** — held. Startup names each of its nine rejection reasons and
   refuses to start rather than serve doubled totals if the reset fails. The one
   place that was fail-closed in the wrong direction — the backup path — is the
   blocking defect fixed above.
4. **No secrets in logs, errors, metrics or audit** — held. MiniMax's provider
   code is synthesised locally and the upstream's own message is discarded;
   credential plaintext is cleared immediately after use; the credential AAD
   binds type and audience.
5. **Determinism on replay** — held. The rollup's key-admission order is ledger
   order precisely so an incremental write and a full rebuild admit the same
   values; verified two ways (byte-identical dumps on the real binary, and a
   code-level experiment across five batch granularities with 237 distinct keys
   crossing the 200-key cap).
6. **Bounded retry/fallback** — untouched.
7. **Pinned Beta ceilings** — held. MiniMax's three rows keep `Defaults ==
   Ceiling`, enforced by a test that walks the profile table. Noted as a
   structural gap, not a regression: nothing anywhere locks a ceiling's
   historical value, so "narrowing only" rests on human review.
8. **Egress through SafeTransport only** — held. The per-connection host
   allowlist is derived server-side from the connection's own endpoint; the
   model-enumeration call uses the same pinned client; loopback, link-local and
   cloud metadata addresses are refused regardless of the private-address
   setting.

## 4 Design

- **Fix-in-place discipline**: clean. `DeleteUsageCheckpoint` was replaced by
  `ResetUsageDerivatives` rather than kept beside it; `PutUsageCheckpoint`'s
  signature changed rather than gaining a second entry point; the registration
  merge deleted the tables it replaced.
- **Format versions**: bbolt 32 → 33 and the usage checkpoint payload 7 → 8, each
  bumped so stale state is refused and rebuilt rather than misread. The rollup
  carries its own `RollupVersion`, checked at startup.
- **One-way doors**: three MiniMax profile IDs, the `minimax-api` access surface,
  the `usage_daily_rollup` bucket and `usage_rollup_state` key, and the
  `/admin/api/v1/usage/summary` response shape.
- **Known gap, recorded rather than fixed**: the new Admin endpoint family has no
  contract guard — it is not in the frozen-route list, not in any manifest, and
  its outer envelope is an untyped map, so renaming a wire key passes the whole
  Go suite. It is the largest new outward surface in this release and the least
  protected.
- **ADRs**: none required by the range.

**Re-init required: no** — verified against a real data directory written by the
v0.4.0 binary, carrying real accounting events, upgraded in place with the
release binary; the rebuilt rollup matches a full offline rebuild row for row.
**Stated in release notes: yes** (CHANGELOG 0.5.0 "Operator impact"), together
with the upgrade's order constraint: back up with the old binary first, and make
`start` the first command run after the swap.
