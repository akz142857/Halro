## P10: authenticate the bytes before deriving usage

The gap affected the active WAL as well as sealed generations. All four offline
commands (`usage compact`, `verify`, `prune`, `rebuild-summary`) used keyless
`InspectReplay`; an edited epoch-4 payload with a repaired CRC was accepted.

The replacement reads metadata without migration, unlocks and verifies the
master key, loads the stable Ledger HMAC key (including its rotation envelope),
and authenticates frames while replaying every generation. It carries the chain
across compressed and uncompressed segments, checks manifest chain endpoints,
and rejects an epoch downgrade across generation boundaries. Legacy epochs 1–3
remain explicitly checksum-only, as required by the existing compatibility
contract.

Before creating the exporter or opening writable metadata, it rejects an
incomplete tail and compares the chain head with the trusted checkpoint. This
also catches removal of complete frames, whose remaining prefix can have valid
MACs. The checkpoint check is shared with `ledger verify`. The exclusive data
lock is acquired through the existing read-only lock path, so a failed command
does not rewrite even the lock file.

Tests exercise forged active and sealed frames with valid CRCs, complete-frame
truncation, partial tails, missing/wrong keys, old metadata schema, compressed
history ending in an empty active generation, master-key rotation and a local
fake KMS becoming unavailable. Failed commands compare every file's SHA-256
before and after, including existing bbolt derivatives and Parquet files.

**Regression proof:** Go's `-overlay` substituted the original `usage.go` from
`cc14e18`, leaving the checkout untouched. Running
`TestOfflineUsageRejectsUntrustedHistoryWithoutWriting/(active_mac|sealed_mac)/rebuild-summary$`
failed for both cases with `untrusted history accepted`. With the repaired
implementation, those same cases pass.

Operator impact: offline usage now needs the master key or primary KMS slot and
the current metadata schema. Before upgrading, use the old binary to back up
and verify. New usage commands refuse old metadata without migrating it; start
the new binary only after the backup. A partial WAL tail must be recovered by
startup before offline usage commands proceed. CHANGELOG records these changes.

## P14: replace the stale reference with a paired comparison

[Archived evidence](../performance/2026-09-03-v0.6.0/README.md) compares the real
v0.5.0 sources with this candidate on one Apple M4 host, Go 1.26.6 and
`GOMAXPROCS=4`. Eight alternating samples per version cover ten benchmark cases;
all 80 package invocations exited 0. The limiter harness is new and identical
on both sides. Existing benchmark bodies were retained unchanged.

The [current baseline](../performance-baseline.md) contains the full table.
Route resolution is 5.198 → 5.233 µs with no significant difference, while both
versions allocate 15,888 B in 41 allocations. The obsolete 405 ns / 1 allocation
figure is explicitly historical and no longer a regression criterion.

Two measured costs are retained in the verdict rather than hidden by a pass:

- Unlimited project admission is **9.82% slower**, 100.8 → 110.8 ns
  (p=0.004); limited admission is **6.30% slower**, 130.9 → 139.2 ns
  (p=0.007). Both remain 200 B / 5 allocations. The request/execution gate
  branches are a plausible source-level explanation, not a profiled attribution.
  The unlimited case is near the 10% investigation threshold and its candidate
  interval is ±13%; this sample does not prove that all future runs stay below it.
- WAL open plus replay is 562.3 → 551.7 ms, with no significant time change
  (p=0.574), but cumulative allocation rises **5.58%**, 220.1 → 232.4 MiB.
  The release adds three strings to `ledger.Event` and a generation to `Record`;
  larger decoded records are consistent with this increase, but this comparison
  is not an allocation profile. The figure is not retained memory or peak RSS.

Fixed Token Guard admission measures +4.59% (p=0.021). The remaining time
comparisons are not statistically significant. No observed median time increase
exceeds 10%, and none of the measured admission/routing/redaction paths adds an
allocation. This closes the missing-comparison gap; it is not an end-to-end
capacity claim or a replacement for the historical 10 GiB recovery experiment.

The standing procedure now requires a fresh previous-tag/candidate comparison
when a published table is stale, and uses measured allocation counts rather than
incorrectly calling routing and Token Guard allocation-free.
