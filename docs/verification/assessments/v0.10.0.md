## Defect and review disposition

Every change in the range reached `main` through a pull request whose gate and
CI were green. No independent second-review claim is made. Defects found while
verifying the HA port were fixed inside the range rather than carried:

- #448: a Replica more than 64 frames behind never caught up (pre-existing on
  `ha`); #450 also fixed a peer-session close that failed when the peer had
  already reset, found as a flake in #450's CI.
- #449: under contention the metadata batch layer queued behind the writer and
  split instead of merging, halving the 64-worker ceiling.
- #450: Replicas exposed no hot-state metric.
- #464: found by this assessment's upgrade measurement — the first start after
  the history format change read the whole old `history.db` (3.2 GB resident
  for a 3.3 GB file) and logged a spurious catch-up failure every minute of the
  rebuild.

The repository had no open issues labelled `bug` when queried on 2026-10-23.
Known limitations recorded in earlier assessments remain.

## Invariants and upgrade impact

1. **Single writer / data directory:** unchanged for Standalone. HA adds
   Primary/Replica members, each owning its own locked directory; not supported
   in production in this release.
2. **Ledger authority:** unchanged. The metadata journal is the authority for
   `halro.db` only; Ledger, usage and audit counts agree at every smoke stage.
3. **Fail closed:** v0.9.2 refuses the upgraded directory rather than writing
   behind the journal; an untrusted `history.db` is replaced and rebuilt from
   the Ledger, as before, only by a new file.
4. **Secret handling:** unchanged; secret-canary scan passed.
5. **Replay determinism:** unchanged.
6. **Bounded retries/fallback:** longer default timeouts for new installs; the
   bounds remain explicit and existing configurations keep theirs.
7. **Capability filtering:** untouched.
8. **Compatibility manifests:** untouched; no northbound or Provider protocol
   change.
9. **Configuration:** new defaults `attempt_response_header_timeout` 5m,
   `route_total_timeout` 10m, `shutdown_timeout` 10m, and the new optional
   `replication` and `metrics.ha_status` blocks; existing files keep their
   values. The published snapshot differs from v0.9.2's in exactly those keys.

Re-initialisation required from v0.9.2: **no**. Rollback fence: **schema 42**;
v0.9.2 was observed refusing an upgraded directory, and the way back is the
pre-upgrade backup, observed working.

## Evidence boundaries

- No production data: the at-scale measurement used a directory v0.9.2 wrote
  with the probe's accounting lifecycle (no Provider traffic, no metadata

- The smoke ran on darwin-arm64; the Linux evidence is the 1 GiB container run
  above and the ordinary CI.
- Package installation acceptance is performed by the downstream release
  workflows; channels must not be described as updated until those pass.
