# v0.9.0 pre-release assessment

Date: 2026-10-17
Range reviewed: `v0.8.5` through the v0.9.0 release commit on `main`.
Assessor: Claude Opus 5.5, on the owner's instruction. Owner: akz142857.

## Recommendation

**GO** for GitHub and GHCR **and for the Homebrew/APT package channels**
(`publish_packages=true`), whose downstream dispatch has now run once with
v0.8.5 and succeeded.

This release is **one-way**: the first start migrates metadata from schema 38
to 41, after which v0.8.5 refuses the directory. It also refuses a v0.8.5
configuration file until `halro config migrate --write` has run. Neither needs
re-initialisation, and both are stated in the CHANGELOG's "Upgrading from
v0.8.5", which is what the Release page will say.

## Defect and review disposition

No defect reports are open against the range: no open issue carries the `bug`
label, and the range adds no to-do, fix-me or XXX markers to Go source.

**Range review (§1b) was a focused seam review, by the owner's decision**, not a
line-by-line read of the 116 production Go files (+12.7k/−3.6k). Every pull
request in the range had its own review; the seam review asked what those could
not see, where two of them meet:

- Sealing on by default (#421) × snapshot start (#421) × governance archive
  (#422): a snapshot whose position lies in a sealed generation resumes
  (`TestLedgerStateResumesFromASnapshotInASealedGeneration`). Sealed
  generations are compressed by default, which that test does not do; a
  throwaway test that compacts generation 1 to `ledger-1.seg.gz` before
  reopening also resumed from the snapshot and matched a full replay. It was not
  committed.
- Hot-state admission (#423/#424) × snapshot start: the set of admitted
  requests is process memory and starts empty, while restored reservations are
  priced from the state, so the estimate is `max(open, reservations)` either
  way. Every request the gateway begins defers `run.close()` (7 of 7 call
  sites), which finalizes and releases it.
- `Idempotency-Key` on inference (#342) × hot-state refusal: a refusal comes
  from `beginRequestRun`, before any attempt, so the claim is still
  `creationReserved` and `settle` deletes it — the key is given back rather
  than burned.
- Built-in key ceiling (#335): its table is keyed by Gateway Key and Project
  IDs, which only an administrator creates, so it is bounded by them and is not
  a new memory growth path.
- Backup × history/archive: backups deliberately carry neither `history.db` nor
  `archive.db` (`internal/app/backup.go`); a restored directory rebuilt both,
  verified below.

Found by the assessment, and their disposition:

1. **The CHANGELOG had no entry for P2 or P3** — the snapshot start, sealing on
   by default, `archive.db` — nor for the hourly reconciliation, the console
   alias headings, the Providers refusal panel or the Go 1.26.9 toolchain.
   Fixed in the release commit, which also merges the section's four `Added`,
   four `Changed` and two `Fixed` subsections into one each.
2. **Sealing on by default does not reach an existing configuration.** A file
   copied from the v0.8.5 example sets `ledger.seal.enabled: false` and
   `max_active_bytes: 8589934592` explicitly, and `config migrate` keeps values
   the operator set, as designed. Observed on the smoke directory below.
   Disposition: step 3 of "Upgrading from v0.8.5" in the CHANGELOG.
3. **`halro doctor` from this release fails on a v0.8.5 directory before its
   first start**: `metadata schema version 38 does not match required version
   41`. `OpenReadOnly` refuses any schema it does not match, which is right for
   a newer schema and unhelpful for an older one that `start` will migrate.
   Not release-blocking — it refuses rather than misreads, and passes after the
   first start. Disposition: documented in "Upgrading from v0.8.5"; a follow-up
   should report a pending migration as such rather than as a failure.

`make full-check` on the release-preparation commit `8394fd39`, Node 22
(`nvm use 22`, v22.18.0) to match CI, in its own worktree: gofmt, shuffled
`go test -count=1 ./...`, full `go test -race -count=1 -timeout=20m`, `go vet`,
the frontend suite, TypeScript checking, production build, artifact/secret

validation (13 recording and 45 alert rules). **Exit 0, 15m39s, no retry.** The
commit after it changes documentation only (this record, the CHANGELOG's
Providers-page entry, the performance baseline and the release guide).

Frontend: 46 files, **677 tests** (624 at v0.8.5). Bundle: **246,994 bytes
gzip** initial, against 241,272 at v0.8.5 — **+5,722 (+2.37%)**, inside the 10%
threshold and the 500 KiB budget; the range's console work (alias headings,
the Providers refusal panel, the usage lists) and the dependency refresh
account for it. Browser artifact secret scan: 29 files clean.

**Performance (§2), mandatory for this range.** Paired comparison of v0.8.5
and `8394fd39` on one host and toolchain, six rounds, archived in
`docs/verification/performance/2026-10-17-v0.9.0/` with raw samples and
metadata. **No time difference is statistically significant** in `budget`,
`ledger`, `limiter`, `provider`, `redaction` or `tokenguard`. Request-lifecycle
allocations fall 2.6–3.5% in all nine combinations; route resolution keeps 41
allocations at +1.72% bytes. The diff scan for serialization found one new

8-core contention, and the lifecycle benchmark above includes it.

`docs/verification/memory-bounded-baseline.zh-CN.md` (Linux container, one
million requests of history): a start from the snapshot in 0.53–0.88 s, a full
rebuild without one in 48–53 s at a flat ~20 MiB heap. The WAL frame layout is
unchanged, so the 10 GiB replay profile still describes the replay itself.

## Invariants and upgrade impact

1. **Single-writer / single data dir** — touched: two new files in the data
   directory (`history/history.db`, `history/archive.db`) and `state.snap`, all
   written by the owning process under its existing lock. No shared-directory
   behaviour.
2. **Ledger WAL is the accounting authority** — touched, and the point of the
   release. The snapshot, the usage history and the archive are each bound to
   the Ledger chain head (and the archive also to the Governance journal hash)
   and rebuilt from the logs when they do not match; none is a balance source.
   Reservation-before-request and atomic settlement are unchanged.
3. **Fail-closed** — touched: a snapshot that is missing, ahead of the Ledger,
   or from a fork is set aside for a full rebuild; a failed archive read is an
   error, never "absent"; the hot-state limit refuses new work with 503 rather
   than growing. The `doctor` behaviour in finding 3 is fail-closed.
4. **No secrets in logs/errors/metrics/audit** — touched by new log lines and
   metrics; none carries key material, prompts or bodies. The Gateway 401 bodies
   in the smoke echoed no key material; the bundle secret scan is clean.
5. **Determinism on replay** — touched: the archive decides a Run's expiry from
   the applied record's `OccurredAt`, not the wall clock, so replay archives the
   same Work Units.
6. **Bounded retry/fallback** — untouched in its bounds; refusal routing (#324)
   changes which targets are admissible, not how many attempts are made.
7. **Capability filtering rejects, never drops** — untouched.
8. **Compatibility manifests** — touched: `GET /v1/models`, `Idempotency-Key` on
   chat and embeddings, and the fixed per-minute ceiling on resource-plane reads
   are in `docs/compatibility/endpoint-manifests.json`. The status change for a
   response-header timeout (502 `provider_error` → 504 `provider_timeout`) is
   not a manifest field; it is called out in the CHANGELOG and in "Upgrading
   from v0.8.5", as the pre-1.0 rule for a wire change asks.
9. **Config semantics** — touched: `ledger.max_hot_state_bytes`, `routing`
   (replacing `circuit_breaker`), the seal defaults, and configuration
   `version: 2`. Each has a default in `default.yaml` and
   `config.example.yaml`, and the configuration-reference gate passes.

**Re-initialisation required: no.** **Rollback fence: yes.** The first start
migrates metadata from schema 38 to 41, after which v0.8.5 refuses to start
(`metadata schema version 41 is newer than this build supports (38)`) and
leaves the directory intact. Rolling back is restoring the backup taken with
v0.8.5 before the upgrade. Configuration must be migrated (`halro config
migrate --write`), and sealing turned on by hand where the file sets it off.

## Evidence boundaries

- **No real-account Provider smoke**, although provider wire behaviour changed
  (#338, #339, #343, #352, #354, #356). The owner decided not to spend on it for
  this release; those changes rest on unit and contract tests only. This is a
  waived pass, not a scoping one.
- **The range review was a seam review**, by the owner's decision; see above.
- **The memory claims come from the redesign's probes, not from production.**
  The heap, start-time and rebuild figures in the CHANGELOG were measured in a
  Linux container (`docs/verification/memory-bounded-baseline.zh-CN.md`).
  Production has never had a heap profile taken; the release adds
  `HALRO_PPROF_LISTEN` so it can be.
- **The first-start rebuild on a production-sized history was not timed here.**
  The smoke directory holds 25 frames; 48 s per million requests is the probe's
  figure.
- No production KMS/PKI, contact-point delivery, clean-host package
  installation or 24-hour soak was run. The formal workflow repeats its
  container scans, SDK compatibility, SSE stress, reproducible packaging, SBOM,
  signature, provenance and pre-publication verification.

**GO**, for GitHub, GHCR, Homebrew and APT.
