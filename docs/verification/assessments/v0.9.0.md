# v0.9.0 pre-release assessment

Date: 2026-10-19
Range reviewed: `v0.8.5` through the v0.9.0 release commit on `main`.
Assessor: Claude Opus 5.5, on the owner's instruction. Owner: akz142857.

## Recommendation

**GO** for GitHub and GHCR and for the Homebrew/APT package channels
(`publish_packages=true`). The owner accepted on 2026-10-19: V-014 (a
`wall_clock_*` pricing quarantine cannot be lifted) ships as a known issue,
with a lift action in a later release; the bbolt freelist growth ships
unmeasured, to be measured before deciding on a `history.db` retention period;
and the real-account Provider smoke stays waived, as on 2026-10-17.

This replaces the 2026-10-17 recommendation, which the owner halted for the
261017 review. That review found two P1s; both are fixed here, one of them
(V-013) present in v0.8.5 and therefore in production today.

This release is **one-way**: the first start migrates metadata from schema 38
to 41, after which v0.8.5 refuses the directory. It also refuses a v0.8.5
configuration file until `halro config migrate --write` has run. Neither needs
re-initialisation; both are in the CHANGELOG's "Upgrading from v0.8.5".

**Range review (§1b).** `v0.8.5..2e749db1` was reviewed by 261017 (stages 1–5:
revert integrity, revalidation of the 260927 findings, a deep read of the
memory-bounded redesign, cross-cutting seams and adversarial re-checks). The 36
commits since were read as one diff for their seams:

- V-002 × V-011: an `accounting_capacity_exhausted` refusal comes from
  `beginRequestRun`'s accounting call, on the error path that now calls
  `releasePolicy`/`releaseTokenGuard`, so a requeued request is neither failed
  for good nor charged again.
- V-013 × the deferred queue: a quarantine answers `accounting_unavailable`,
  which `deferredAdmissionRefusal` does not requeue, so a quarantined deployment
  cannot spin a deferred Response.
- V-001 × V-012 in the usage collector: a failed write sets lagging and `Run`
  then drains queued records without applying them; `CatchUp` first writes the
  held batch back, clears lagging only once that write and the replay succeed,
  and applies under the same lock `Run` drains under.
- V-010: `observeClaimed` releases the gate lock before flushing, and skips the
  scope `observeReporting` is about to record, so no failure is counted twice.

No new finding.

## Invariants and upgrade impact

1. **Single-writer / single data dir** — touched: two new files in the data
   directory (`history/history.db`, `history/archive.db`) and `state.snap`, all
   written by the owning process under its existing lock. No shared-directory
   behaviour.
2. **Ledger WAL is the accounting authority** — touched, and the point of the
   release. The snapshot, the usage history and the archive are each bound to
   the Ledger chain head (and the archive also to the Governance journal hash)
   and rebuilt from the logs when they do not match; none is a balance source.
   A usage-history write failure now stops the collector applying records until
   a catch-up from the Ledger succeeds (#430, #433), so the index is rebuilt
   from the authority rather than patched from whatever was held in memory.
   Reservation-before-request and atomic settlement are unchanged.
3. **Fail-closed** — touched: a snapshot that is missing, ahead of the Ledger,
   or from a fork is set aside for a full rebuild; a failed archive read is an
   error, never "absent"; the hot-state limit refuses new work with 503 rather
   than growing. `doctor` refusing a v0.8.5 directory before its first start
   (261017 V-005) is fail-closed. The pricing clock check (#434) still
   quarantines a real wall-clock jump — drift between the wall and monotonic
   clocks beyond the tolerance, or a rollback across a restart against the
   durable high-water mark — and no longer quarantines for a metadata write
   that was merely slow (V-013). A quarantine still cannot be lifted (V-014).
4. **No secrets in logs/errors/metrics/audit** — touched by new log lines and
   metrics; none carries key material, prompts or bodies. The Gateway 401 bodies
   in the smoke echoed no key material; the bundle secret scan is clean.
5. **Determinism on replay** — touched: the archive decides a Run's expiry from
   the applied record's `OccurredAt`, not the wall clock, so replay archives the
   same Work Units.
6. **Bounded retry/fallback** — untouched in its bounds; refusal routing (#324)
   changes which targets are admissible, not how many attempts are made.
7. **Capability filtering rejects, never drops** — untouched.
8. **Compatibility manifests** — touched: `GET /v1/models`, `Idempotency-Key` on
   chat and embeddings, and the fixed per-minute ceiling on resource-plane reads
   are in `docs/compatibility/endpoint-manifests.json`. The status change for a
   response-header timeout (502 `provider_error` → 504 `provider_timeout`) is
   not a manifest field; it is called out in the CHANGELOG and in "Upgrading
   from v0.8.5", as the pre-1.0 rule for a wire change asks.
9. **Config semantics** — touched: `ledger.max_hot_state_bytes`, `routing`
   (replacing `circuit_breaker`), the seal defaults, and configuration
   `version: 2`. Each has a default in `default.yaml` and
   `config.example.yaml`, and the configuration-reference gate passes.

**Re-initialisation required: no.** **Rollback fence: yes.** The first start
migrates metadata from schema 38 to 41, after which v0.8.5 refuses to start
(`metadata schema version 41 is newer than this build supports (38)`) and
leaves the directory intact. Rolling back is restoring the backup taken with
v0.8.5 before the upgrade. Configuration must be migrated (`halro config
migrate --write`), and sealing turned on by hand where the file sets it off.

## Evidence boundaries

- **No real-account Provider smoke**, although provider wire behaviour changed
  (#338, #339, #343, #352, #354, #356). The owner decided on 2026-10-17 not to
  spend on it (261017 E09 BLOCKED) and confirmed that on 2026-10-19; those
  changes rest on unit and contract tests. This is a waived pass, not a scoping
  one.
- **The 261017 review read the memory-bounded redesign in depth and the rest
  of the range by seams**, by the owner's decision in its plan.
- **The memory claims come from Linux-container probes and soaks, not from
  production.** Production has never had a heap profile taken; the release
  adds `HALRO_PPROF_LISTEN` so it can be.
- **bbolt's freelist bound is not measured.** E05b shows it growing with
  `history.db` (the only growth found); how far it grows per million requests,
  and whether `history.db` needs a retention period, is follow-up work.
- **The first-start rebuild on a production-sized history was not timed.** The
  smoke directory rebuilt 518,416 frames in 10 s on this host; the probe's
  figure is 48 s per million requests in a Linux container.
- **E04 read-only and slow-disk faults were not run** (they need a privileged
  container and block-device throttling). V-013 is the class of bug a slow disk
  exposes; it was found by a soak's own disk pressure instead.
- No production KMS/PKI, contact-point delivery, clean-host package
  installation or alert delivery was run. The formal workflow repeats its
  container scans, SDK compatibility, SSE stress, reproducible packaging, SBOM,
  signature, provenance and pre-publication verification.

## Publication verdict

**GO**, for GitHub, GHCR, Homebrew and APT, with the owner's acceptances of
2026-10-19 above.

The full gate passed clean on the first run; the hot path shows no regression
against v0.8.5 on the same host, with Token Guard's small cost explained; the
candidate upgrades a directory the previous release wrote, verifies every chain
on it, resumes and rebuilds to the same state, and a backup it takes restores
and starts. The two P1s the review found are fixed and confirmed on real
binaries, one of them (V-013) by continuing the very soak that exposed it.
What this release carries is an upgrade that cannot be undone in place — the
schema migration fences v0.8.5 out, the configuration must be migrated, and
sealing must be turned on by hand where the file says otherwise — and one
known issue that matters operationally: a pricing quarantine from a real clock
jump has no product path to lift it (V-014). Both are on the Release page.
