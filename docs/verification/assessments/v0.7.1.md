# v0.7.1 pre-release assessment

Date: 2026-09-07
Range reviewed: `v0.7.0` (`3252afa6688466215b3dda68a1aca8725fa4f41a`)
through the v0.7.1 release commit on `main`.
Assessor and owner: ziy

## Recommendation

**GO for v0.7.1 publication, subject to a green exact-SHA release dry run.**
The owner explicitly requested publication on 2026-09-07. The formal workflow
must use the same `main` commit as the dry run and must not start if `main` moves
between those two runs.

## Scope and triggered passes

The release range adds Debian, Homebrew, and APT packaging automation; changes
the release control plane to create its tag after the gates and dispatch the
exact published commit downstream; corrects Run Governance evidence-detail
layout; and adds the `administrators_required` MFA policy.

This triggers the full Go and frontend gates, generated-bundle verification, a
focused admin-auth security review, config compatibility review, and release
supply-chain review. It does not touch provider wire behavior, the inference
request hot path, accounting, the Ledger, the Governance Journal, bbolt data
schemas, Parquet, Usage checkpoints, or backup formats. No billable real-provider
smoke or request-path benchmark is triggered.

## Defect and security review

- Range review found no release-blocking correctness, authentication,
  authorization, packaging, or workflow defect.
- MFA enforcement is derived centrally from both policy and account role. An
  unenrolled `read_only` account is exempt only under
  `administrators_required`; an administrator still fails closed until enrolled.
  Existing `optional` and `required` behavior remains covered by regression
  tests, and reader accounts retain no write authority.
- Existing reader MFA enrollment is not silently ignored: if a reader has an
  active authenticator, login continues to require its code until the
  authenticator is disabled or removed through the existing authenticated flow.
- The release workflow has one entry on `main`, rejects reused tags, creates the
  tag only after its quality and artifact gates, verifies source SHA/ref and
  workflow identity in attestations, and sends the exact version plus full
  commit to both downstream package repositories.
- No new secret value is stored in the repository or printed by the workflows.
  The formal downstream chain still depends on the repository-scoped GitHub App
  and protected APT signing environment documented in the operator checklist;
  the dry run deliberately cannot validate those publication credentials.

## Quality evidence

The candidate tree passed `make check`: shuffled full Go tests, full race tests,
vet, all 44 frontend Vitest files (564 tests), and Prometheus/Alertmanager
validation. It also passed a fresh deterministic production rebuild after
`npm ci`, the browser-artifact secret scan, npm audit with no vulnerabilities,
the dependency/license drift gate, and `git diff --check`. The implementation
commit's first `main` CI exposed a generated-bundle drift caused by building
without first reinstalling the lockfile dependencies; this release commit
contains the corrected lockfile build and will not be published unless both its
`main` CI and exact-SHA release dry run pass.

A real candidate binary stamped `v0.7.1` was built successfully, reported that
version through `halro version`, and accepted the complete annotated example
through `halro config check`. No provider request was made.

The release dry run is the final exact-commit gate for Go tests including race,
vet, vulnerability scanning, fuzz and SDK compatibility; frontend tests, audit,
build and bundle drift; SSE stress; container scanning; reproducible binary and
Debian packaging; SBOMs; signatures; and provenance attestations.

## Upgrade and rollback

No durable data format or schema version changes. Existing v0.7.0 configurations
using `optional` or `required` load unchanged, and existing data directories need
no migration or reinitialization. The new enum value is intentionally unknown to
v0.7.0, so rollback from a configuration that uses
`administrators_required` requires changing it to `required` or `optional`
before starting the old binary; refusal is explicit and occurs before service
startup.

## Performance and invariants

The request path and persistence paths are untouched, with no new locks,
channels, retries, serialization, or replay behavior. The freshly locked
frontend build is 221,573 gzip bytes for the gated entry set, 3.74% above the
v0.7.0 baseline of 213,586 bytes and below the 10% investigation threshold.

The single-writer/data-directory boundary, Ledger accounting authority,
fail-closed request handling, secret-redaction boundary, deterministic replay,
bounded retry/fallback, capability rejection, and provider compatibility
manifests are untouched. The only config extension is a closed enum whose
default remains `optional`; examples and bilingual operator documentation cover
the new value. No new public endpoint, metric, event kind, or architectural rule
requires an ADR.

## Verdict

**GO — ziy, 2026-09-07**, conditional only on a green release dry run at the
exact commit subsequently used by the formal release workflow. Re-initialization
required: **no**. Billable real-provider smoke: **not triggered and not run**.
