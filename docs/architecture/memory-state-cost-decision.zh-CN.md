## 同费用块 bank 复测：一千筛选通过，一万再次失败

## 冻结与实际链路

原始当前快照 3050 个完整输入；分段观察的基线 3051 个输入、内联候选 3052 个输入。两者差异只在 `internal/scratchstate/tree.go` 与新增边界/篡改测试，观察覆盖层相同。实际二进制、输入 SHA256、容器镜像和命令见[本轮证据](../verification/performance/2026-10-07-memory-state-cost-decision/README.zh-CN.md)。Go 1.26.6，Linux arm64，2 CPU，2 GiB cgroup、无 swap、GOMEMLIMIT=768 MiB，独占 fully allocated host backing、loop DIO=1、ext4，禁网，不使用生产数据或真实提供商。

一千请求由原生 writer 持久化五千事实，沿真实备份验证、停机迁移、七根共同激活、账务/Usage 对账、实际 Close，再由全新进程重开并再次对账。此 fixture 不发送 Gateway 业务请求；它不能证明业务吞吐或 64 路业务成功。seed/restart 为两个进程但共用同一 cgroup，重开使用已有文件系统缓存，不能标成独立 cold-cache 重启。

初轮复合键端到端试验时同机此前的十万实验仍产生大量 IO，该初轮只有一组 A/B，原生并发落盘顺序和生产随机树密钥也不完全相同。耗时差是诊断值，不是可保证的加速比。组件基准固定测试 MAC 密钥与操作顺序，职责另行列明。

## 下一项改动的具体边界

本节的同 job 参考复用要求现已实施；后续布局原型边界继续适用。首先合并同一备份任务内的独立参考构建。`backup.go` 的 `validateBackupPricingProjection` 与 `withBackupUsageReference` 使用同一 staged native 路径、key 和 `ChainReport`，但分别调用 `withPackedBackupReference`；后者内部会完整建立 Ledger。应让一次私有 Ledger owner 同时服务 Metadata 的 `WithFreshPricingView` 校验及 Usage 参考构建，仅在原 job callback 内复用。

这项复用必须保留以下条件：

- 私有参考仍从 staged native 完整认证生成，不能使用 live projection、旧缓存或最终候选自己证明自己。
- 明确绑定实际 native FD/身份、完整 report/cut、同一 Manager 和取消上下文；入口与两次使用结束均核对源。任一变化/未知 Close 失败并保留原 owner 义务。
- 发布/未发布 Usage archive 两个分支都完成价格引用校验；日期、全部 archive 文件验证和 Restore 不减项。跨 job、角色、不同 staged source 或 key 不复用，兼容旧格式各自覆盖。
- 先以实际差分和故障用例核对校验义务，再重新冻结完整输入、三组一千和同一万门槛；阶段序列变化是合法候选改动，必须说明被消除的是重复参考，不能靠改 fixture 前置状态省掉职责。

复用之后的排序批原型已完成并首次通过一万原门槛，见最新节。本节保留此前改动前的范围要求：布局原型只覆盖 `projectionRows` 的 get/put/delete/floor 与完整有序导出：评估以有限排序批和认证磁盘归并降低逐事实随机树改写。事件幂等查询、迟后事实、删除/缺失证明、完整键集合、实际 FD 核对及 owner 收尾须全部成立；普通 bbolt 的结果不能直接授信。原型不得同时更改最终七根、角色权限或共同发布。缓存容量试调到此收口，不沿历史规模不断加大 RAM 或时间上限。
