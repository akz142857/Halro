## Findings

### REL-01 — Dead-man sends a new sequence before persisting it

- Type/status: confirmed implementation defect; P2, high confidence. Owner: dead-man maintainer. Independent counter-review: not yet performed.
- Locations: `internal/deadman/engine.go:133-141`, `:319-331`, `:351-362`; receiver contract `deploy/observability/external-probe/RECEIVER-CONTRACT.md:7-17`.
- Reachable trigger: ordinary `Engine.Run` starts the delivery worker before `Tick`. A tick enqueues a heartbeat, unlocks state and wakes delivery before its probes and final state save complete. The worker calls `send` before any durable save of this new sequence. Crash after external acceptance but before the subsequent local save leaves the disk sequence behind the receiver. A restart uses the same probe ID and reuses an event ID for a different observation.
- Expected: externally visible event IDs remain unique across restart, with the outgoing event/sequence durable before delivery. The contract explicitly calls this a durable FIFO outbox and requires receiver idempotency/replay rejection.
- Actual evidence: socket-free Go overlay blocks a probe, invokes the production `drainOne`, and observes the disk from its in-memory HTTP transport. Output: `at outbound request: disk sequence=0 memory sequence=1 disk outbox=0`; constructing restarted state using production `loadState` and `enqueue` produces `review-00000000000000000001` again. Test exit 0 means the defect observation was reproduced, not that the desired invariant passed.
- Existing defenses examined: tick/state locks, in-flight heartbeat protection, FIFO ordering, bounded outbox, synced atomic state replacement, retry after audit failure. They protect concurrent manipulation and previously saved state but none persists the new sequence before `send`. Receiver replay rejection mitigates false freshness but can reject the new observation as a duplicate. Subsequent higher sequences normally recover; this is not evidence of permanent paging loss or accounting corruption.
- Reproduction: `go test -count=1 -overlay /private/tmp/halro-reliability-review/overlay.json ./internal/deadman -run '^TestReviewSendBeforePersist$' -v`; exit 0, log `repro.log`, package time 3.613s. Overlay source `review_test.go` is retained beside the JSON mapping. It uses no real HTTP service and no process kill; the crash boundary is demonstrated by loading the still-old disk snapshot at send time. This is a package-level interleaving reproduction, not a power-loss filesystem experiment.
- Minimal direction: durably reserve the sequence and outbox entry before exposing it to delivery, while preserving the existing nonblocking-probe/heartbeat behavior. Acceptance: receiver-accepted event followed by simulated crash before acknowledgement persistence must retry the same event or advance to a unique new ID; never reuse that ID with a changed observation. Include initial startup and later ticks, write/sync failures, slow probes and slow receiver cases.

### REL-02 — Interval stats corrupt queue gauges

- Type/status: confirmed implementation defect; P2, high confidence. Owner: CLI/observability maintainer. Independent counter-review: not yet performed.
- Locations: `cmd/halro/stats.go:61-70`, `:91-92`; source metric types `internal/app/metrics.go:301-304`; entry `cmd/halro/main.go:224-255`.
- Reachable trigger: authenticated operator runs `halro stats --interval 1s` while queue capacity stays constant and queue depth stays constant or grows.
- Expected: counters are differenced; queue depth and capacity show the latest sample. Actual: any nondecreasing sample is subtracted, irrespective of type. A queue changing 10 -> 15 at capacity 1024 displays `WAL queue 5 / 0`. A steady nonempty queue displays 0 / 0.
- Existing defenses: decreasing values use the latest sample, which handles the existing falling-gauge test and counter resets; it does not distinguish gauges from counters. Single-snapshot stats and raw Prometheus metrics remain correct. Loopback-only URL validation, disabled proxies/redirects and request timeout protect credentials but do not correct the report.
- Reproduction: `go test -count=1 -overlay /private/tmp/halro-reliability-review/stats-overlay.json ./cmd/halro -run '^TestReviewIntervalQueueGauge$' -v`; exit 0, package time 0.834s; `stats-repro.log` contains `WAL queue 5 / 0`. Overlay source: `stats_review_test.go`. This tests the exact delta/report functions without a running instance.
- Test gap: `TestStatsWindowSubtractsTheEarlierSample` at `cmd/halro/stats_test.go:94` checks only a falling queue gauge and omits capacity. Minimal direction: explicitly preserve gauges or parse/store metric types. Acceptance: unchanged, increasing, decreasing and newly appearing gauges all show the second value; monotonic and reset counters retain correct window behavior.
