## 最优先处理的三项

| 发现 | 可达条件与实际影响 | 决策 |
| --- | --- | --- |
| [SEC-01：换钥遗漏留存密文](findings.md#sec-01) | 仍有capture或本地资源时更换Master Key/DEK，操作报告成功，但旧对象未迁移，新钥无法解密；旧钥可解。file与fake-KMS DEK均复现，same-DEK KEK rewrap不属该根因 | 在下一次相关轮换/发布前修复完整密文生命周期，或明确限制该操作；不是声称所有数据不可恢复 |
| [SEC-02：注销会话可被刷新写回](findings.md#sec-02) | 刷新到期的并发请求在logout删除后upsert；真实logout200后新请求仍接受同一cookie。需要持有原token并命中竞态；generation/绝对过期仍有效 | 会话refresh应条件更新，不得重新创建已撤销行；仅清cookie不能修复服务器撤销 |
| [PROV-01：已接受响应被误判为安全重试](findings.md#prov-01) | OpenAI unary Chat已返回200，但body/envelope不可用；缺少ambiguity导致两次出站、两次零费结算。真实adapter及带价格snapshot/pin/正预留的gateway均复现 | 修正结果不确定性分类；不能据零usage认定上游未执行，也不能以禁掉全部fallback替代边界修复 |

这些是受控复现，不是生产事故通报。PROV-01没有证明真实上游实际扣费；SEC-02没有证明token窃取或匿名绕过；SEC-01没有证明旧钥也无法恢复。严重度来自关键契约被破坏，而不是扩大推测。

## 架构结论

单进程、单写者、Ledger为账务权威的主轴仍清楚。Gateway与Admin身份域分离，治理准入先于上游调用，价格快照、资金预留、审计intent和恢复路径使关键状态可解释。模型“存在性”和“能力证据”在源码与本地UI中保持分离；没有据模型ID自动授予未知能力。Realtime与HA仍分别是设计/提案范围。

主要风险位于跨组件交接：上游响应交给重试/计费时丢失不确定性；会话读—删—写缺少条件事务；密钥迁移只覆盖部分持久对象；Usage从内存交给磁盘时summary缺少一致视图。局部模块的锁、AEAD、WAL事务和单测各自成立，仍不足以守护完整产品契约。

`internal/app`集中装配、管理与运维逻辑，部分核心依赖仍指向协议/Provider类型，当前“协议中立”不是纯依赖层面的完全隔离。建议围绕状态转换与证据归属逐步提炼接口，优先修上述具体接缝；不因文件大或偏好某种架构就提出大范围重写。
