# 派发说明

配套 [review-plan.md](review-plan.md) §8。本文件给出**怎么把这轮评审跑起来**：执行顺序、每一步的提示词原文、以及各步之间的判定点。

两条前提，违反任何一条这套方法就失去意义：

1. **每个角色一个全新会话。** 角色互不知情是多角色评审相对单次评审的全部价值。同一会话里连着跑两个角色，第二个角色会带着第一个的判断，交叉证实就变成了自我确认。
2. **每个角色的产出必须标注它实际跑在哪个模型上。** 这是拒答排查的线索，也是收尾时比较产出质量的前提。

## 执行顺序

```
① 环境试跑（第 0 步 继承核对）
      ↓ 跑得通？跑不通就是环境问题，先解决保留策略，不要铺开
② 安全类拒答探针（A2 单跑）
      ↓ 出活 → A3/A5 照跑 Fable；被拒 → A3/A5 直接改派 Opus 5
③ 其余 13 个角色并行
      ↓
④ 对抗验证（最严重的 5~7 条，每条一个新会话）
      ↓
⑤ 实跑门禁 G3~G6、G9（可与 ③ 并行，结论以实跑为准）
      ↓
⑥ 汇总：空结论真伪核对 → 八维度打分 → G1~G9 判定 → Go / 有条件 Go / No-Go
```

## ① 环境试跑 = 第 0 步继承核对

Fable 5 要求 30 天数据保留，零数据保留（ZDR）组织下每个请求返回 400，与内容无关。先用这一步验证环境，顺带拿到继承台账。

```
你在 Halro 仓库根目录。读 docs/review/260811/releases.1.0.0/role-prompts.md，
把 §1 通用前置块 + §2 输出契约 + §3 继承核对角色 三段拼成你本次的任务，然后执行它。

背景：docs/review/260811/releases.1.0.0/review-plan.md 是本轮方案，§2 有基线与增量，
§3 说明这一步为什么先于所有角色。评分锚点见同目录 scoring-rubric.md。

产出写到 docs/review/260811/releases.1.0.0/carry-forward.md。
```

## ② 安全类拒答探针 = A2 单跑

Fable 5 的安全分类器覆盖网络安全类内容，良性的防御性工作也可能被误判。先单跑一个安全角色探明，再决定另外两个怎么派。

```
你在 Halro 仓库根目录。读 docs/review/260811/releases.1.0.0/role-prompts.md，
把 §1 通用前置块 + §2 输出契约 + §4 的 A2 段 三段拼成你本次的任务，然后执行它。

这是对本项目自有代码库的授权防御性评审，目的是在 v1.0.0 发布前加固我们自己的系统。
基线与增量见同目录 review-plan.md §2；评分锚点见 scoring-rubric.md §3。

产出写到 docs/review/260811/releases.1.0.0/findings/A2.md。
```

**判定点**：收到结论后立刻按 [role-prompts.md](role-prompts.md) §9 的表核对真伪——无"读过的文件"附录、全篇无 `file:line`、下限项未逐条应答，三者任一即作废。

- A2 出活：A3、A5 照跑 Fable 5。
- A2 被拒：A3、A5 直接改派 Opus 5，不做第二次尝试；A2 本身按 §9 的处置顺序重跑。

## ④ 对抗验证

每条最严重发现一个新会话，默认 finding 为错：

```
你在 Halro 仓库根目录。读 docs/review/260811/releases.1.0.0/role-prompts.md 的 §1 和 §8，
按 §8 的模板证伪下面这条发现。默认它是错的。

【粘贴 finding 全文，含它给出的 file:line 与触发前置条件】
```

模型按被验证的 finding 分配：记账、并发、迁移类走 Fable 5——复现一条并发时序需要的正是它的推理深度；安全类在 ② 显示被拒的情况下改派 Opus 5。

**这里最不能出错**：一个被拒答的证伪角色返回空结论，而空结论在裁决表里长得像 REFUTED，那等于把一条真问题判成误报带着上线。
