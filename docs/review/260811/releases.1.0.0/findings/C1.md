### F-C1-01 · `docs/runbooks/` 缺 Master Key 轮换 runbook

- **实跑结果**：轮换过程本身**完全走得通**（见 §5.2），问题只在于它不在事故中会被检索到的位置。

### F-C1-02 · break-glass 命令缺 `--config`，事故中会打到另一个实例

- **级别** P2 ｜ **类型** 问题 ｜ **是否阻塞 v1.0.0**：否
- **证据**：`docs/runbooks/gateway-key-compromise.md:103` 给出
  `halro key disable --key-id <keyID>`，不带 `--config`。CLI 的默认值是相对当前工作目录的
  `config.yaml`（`cmd/halro/main.go:539`：`flags.String("config", "config.yaml", ...)`）。
- **触发前置条件**：运维在非配置目录下执行（源码检出目录、`/root`、任意 CI 工作区）。
- **实跑结果**：我在仓库根目录按 runbook 原文执行，命令加载了**另一份** `config.yaml`，
  返回 `halro: load gateway key: record not found`。事故中这句话会被读成"这把 key 不在
  这里 / 已经处置过"，而不是"你指错实例了"。命令在 `GetGatewayKey` 失败即返回，未发生任何
  写入（`internal/app/keys.go:65-73`），所以后果是误判而不是误改——但 runbook §1:21 恰好
  警告过"零记录不等于撤销过"这一类误判。
- **修复方向**：**修文档**（命令补 `--config <path>`）。若要更稳，**修代码**让缺省 config
  路径在找不到目标记录时把已加载的 `data_dir` 打进错误里。

### F-C1-03 · runbook 承诺的 412 在第一次尝试时拿不到

- **级别** P3 ｜ **类型** 建议 ｜ **是否阻塞 v1.0.0**：否
- **证据**：`docs/runbooks/gateway-key-compromise.md:63` 写「`If-Match` 缺失返回 `428`，
  不匹配返回 `412`」。实测顺序是：缺失 → `428 If-Match revision is required`（一致）；
  **不匹配且请求体为空 → `401 recent_reauth_required`**（`internal/app/admin_stepup.go:39`

- **触发前置条件**：运维按 runbook 先只带 `If-Match` 试一次。
- **修复方向**：**修文档**，注明 412 只在二次验证材料已通过后才可见。

### F-C1-04 · 恢复会复活已撤销的 Gateway Key，工具侧零提示

- **级别** P2 ｜ **类型** 问题 ｜ **是否阻塞 v1.0.0**：否（但应进发布说明）

- **触发前置条件**：泄露处置之后、从处置时间点之前的归档恢复。

### F-C1-05 · 轮换后旧备份被拒，错误信息不指向真正的原因

- **级别** P2 ｜ **类型** 问题 ｜ **是否阻塞 v1.0.0**：否

### 5.2 必做项 2 · Master Key 轮换 —— **走通**（file 模式；key_slots 无法验证）

按 `docs/guides/operator-guide.md:256-303` 实操（该过程不在 `docs/runbooks/` 下，见 F-C1-01）：

```
# 1. 先创建并验证一份备份（文档要求）
halro backup create --config .../inst1/config.yaml --output .../halro-pre-rotation.hmbk --key-file .../backup.key
  → backup_id bkp_6dc028d2f95fc03107529f47b2825815
    master_key_fingerprint sha256:9f10ad2b...   ledger_watermark {gen 1, off 21350, seq 20}

# 2. 停机（已停），保留旧 key
cp .../inst1/master.key .../old-master.key

# 3. 生成替换 key（文档原文）
umask 077 ; openssl rand 32 > .../new-master.key      → -rw------- 32 bytes

# 4. 轮换
halro key rotate --config .../inst1/config.yaml --new-key-file .../new-master.key
  → {"old_fingerprint":"sha256:9f10ad2b...","new_fingerprint":"sha256:9b20ac00...",
     "old_key_version":1,"new_key_version":2,"credentials":1,"recovered_pending":false}
```

轮换后核验：

| 项 | 结果 |
|---|---|
| 活跃 `master.key` 是否已换成新 key | 是（`9b20ac00…` == new-master.key 的 sha256） |
| `halro doctor` | `healthy=true`、`vault_status=verified`、`master_key: pass` |
| Ledger 链 | `committed sequence 20 at offset 21350; chain authenticated (20 frames)`，chain hash 与轮换前逐字节相同 |
