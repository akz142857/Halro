# Halro 全系统界面精简与体验升级方案

- 日期：2026-11-04
- 状态：已实施并完成本地前端验收；源码随本次变更提交，未发布正式版本
- 范围：Web Admin Console 全部 12 个主页面、认证入口、首次引导、设置子页面，以及弹窗、抽屉、列表、表单和各类状态
- 依据：用户提供的「创建服务商」截图、当前前端源码、现有设计系统，以及 Apple Human Interface Guidelines（HIG）
- 实施证据：[实施与验收记录](../review/261104-console-simplification/execution.zh-CN.md)。正文保留原设计意图，最终实现、审查修正与证据边界以该记录为准

## 1. 目标与设计判断

**让标题、布局和控件承担解释工作。默认界面只呈现完成当前任务所需的信息，其余内容在相关时出现。**

本次升级同时处理信息结构、文案、交互和视觉层级。仅把文字变淡、字号变小，或把所有段落塞进问号，都不能解决当前问题。

目标体验：

1. 打开页面即可识别对象、状态和主要操作，无需先读一段产品说明。
2. 常规操作只面对必要字段；专业配置有明确入口，已修改项能在收起后看见摘要。
3. 同一事实只出现一次，标题和标签已说明的事情不再补一句解释。
4. 错误、风险、费用和权限边界在需要做决定的位置出现，并提供下一步。
5. 同一组件在所有页面具有一致的密度、层级和交互方式。

### Apple HIG 的采用方式

采用其简洁、层级、渐进披露、可恢复和可访问原则，将其转译为跨平台 Web 控制台规则：

| Apple 官方指南 | 本项目采用方式 |
| --- | --- |
| [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles) | 每个元素有明确用途；标题、内容与主操作构成稳定层级 |
| [Layout](https://developer.apple.com/design/human-interface-guidelines/layout) | 用对齐、分组和间距组织内容，减少嵌套容器 |
| [Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls) | 常用项直接呈现，低频配置和技术详情逐步展开 |
| [Writing](https://developer.apple.com/design/human-interface-guidelines/writing) | 标签准确，按钮描述动作，辅助文字只补充新增信息 |
| [Offering help](https://developer.apple.com/design/human-interface-guidelines/offering-help) | 帮助贴近上下文；需要长篇解释的控件优先考虑重新设计 |
| [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts) | 警告用于需要注意或决策的情况，避免长期展示无行动意义的提示 |
| [Color](https://developer.apple.com/design/human-interface-guidelines/color) | 强调色有节制；状态不能只靠颜色区分 |

后文具体尺寸、文案长度和减量目标是 Halro 的拟定标准，并非 Apple 的强制数值，也不表示通过 Apple 认证。沿用 Halro 品牌、Light/Dark 和系统字体。

## 2. 已确认的结构性问题

| 证据位置 | 当前情况 | 改进方向 |
| --- | --- | --- |
| `web/src/components.tsx` 的 `PageHeader` | `eyebrow`、`description` 都是必填，并始终渲染 | 允许仅标题与操作；说明按必要性添加，避免空占位 |
| 多个页面的 `PageHeader` 调用 | 页面前言解释模块职责、内部机制或数据来源 | 删除职责复述；数据范围、时效和特殊限制移到实际数据附近 |
| `ProvidersPage.tsx` 的服务商表单 | 分组说明、字段帮助、能力摘要、能力勾选区同时出现 | 重组为基础信息、能力、连接选项；同一能力信息只呈现一次 |
| 同一表单的代理提示 | 当前无条件展示完整「代理信任边界」，直连也会看到 | 根据代理选择展示相关内容；高风险能力的上游联网提示另行判断 |
| 同一表单的页脚 | 「启用服务商 · 已启用」加一句正常状态解释 | 使用一个有标签的状态控件；异常或变更后果才补充说明 |
| `web/src/design-system/` 与 `docs/design-system/` | 已有主题、Token、资源行、反馈位置和无障碍约束 | 扩展现有系统；新增信息取舍规则和统一折叠契约 |

仓库已有 [全面视觉评审方案](../prd/admin-visual-system-review-plan.zh-CN.md) 和持续维护的 [设计原则](../design-system/visual-principles.md)、[组件契约](../design-system/components.md)、[页面模式](../design-system/patterns.md)。本方案补充「信息精简与任务呈现」的执行范围。旧方案的阶段状态与当前迁移表存在历史差异，阶段 0 需依据源码重新核对，不沿用旧完成度数字。

## 3. 全系统统一的信息取舍规则

### 3.1 每条文字必须有去向

| 分类 | 判定 | 处理与示例 |
| --- | --- | --- |
| 删除 | 复述标题、控件名称、当前值或正常状态 | 「选择直连，或选择代理」；「启用后可以使用」；「模型部署」上方再次写「模型部署」 |
| 默认可见 | 做当前决定必需，且从标签和值无法推断 | 费用未知、密钥仅显示一次、当前只读、数据仅为本节点视角 |
| 条件出现 | 只有特定选择或状态下才相关 | 选择代理后的信任摘要；关闭资源后的影响；凭据端点不匹配；订阅使用约束 |
| 展开查看 | 排障或低频配置需要，常规任务无需阅读 | API 路径、Profile ID、完整 TLS 说明、原始 JSON、证据详情 |
| 文档承载 | 概念教学、实现原理、完整操作教程 | 网关架构、能力证据体系、CONNECT 工作原理；提供具体主题链接 |

顺序：先检查能否通过准确标签、合理默认值或布局消除困惑，再决定是否添加说明。

### 3.2 必须保留的信息

以下信息可以缩写或结构化，但不能因为精简而消失：

- 删除、轮换、停用、扩大权限等操作的对象与实际后果。
- 付费请求、能力探测可能产生费用，以及需要显式接受的订阅使用限制。
- 密钥只显示一次、保存现有秘密的规则、明文认证与网络访问例外。
- 费用未知、账本不完整、数据过期、局部失败、只读和权限不足。
- 能力的未知、声明、目录、上游元数据或检测来源；不能把未知展示为已支持。
- 设置作用域（当前管理员/全实例）与生效方式（即时应用/需要重启）。
- 提交失败的原因与可执行的恢复步骤。

具体约束：

- 字段标签保留，placeholder 不替代 label。
- 关键后果直接可读，不能仅在悬停或问号中显示。
- 折叠区域存在校验错误时自动展开，并定位到首个错误。
- 已配置的非默认值在折叠标题旁显示摘要；不能收起后看起来像未配置。
- 未配置与无匹配筛选结果使用不同空状态，前者给创建入口，后者给清除筛选入口。
- 不把所有操作改为图标。创建、保存、删除等动作优先保留明确文字。

### 3.3 文案规格

- 页头默认「标题 + 必要上下文 + 主操作」；不默认展示英文眉题或模块介绍。
- 区块优先「标题 + 控件/内容」，没有新增信息就不写副标题。
- 普通字段帮助以一句为目标；超过一句时重新评估控件设计或提供展开详情。
- 技术概念使用稳定术语。例如将「能力实现」候选调整为「API 接口」，选项使用「Chat Completions」「Responses」等可辨识名称，路径进入详情。
- 「热加载」等实现措辞改为结果措辞，例如「创建并应用」「保存并应用」。实际未应用成功时必须显示真实状态，不能仅因保存成功就称已生效。
- 数值的单位、0/空值的含义、时间范围和时区保留在标签、后缀或必要短提示中。
- 中文和英文同步按语义改写，避免英文仅机械缩短或因长度被截断。

注意：截图没展示的凭据选择等内容，仍是完成任务的必要步骤，必须纳入首层设计。

### 4.2 建议结构

以下为结构线框，不是最终视觉稿；所选能力数与配置摘要均由真实状态生成。

```text
创建服务商                                      ×

名称          [                               ]
服务商        [ OpenAI ▾ ]
API 接口      [ Chat Completions ▾ ]
凭据          [ production · api.openai.com ▾ ]
API 地址      [ https://api.openai.com         ]

开放能力      已选 11 项                   调整 ›
连接选项      直连 · 使用默认并发上限           ›

☑ 启用服务商                取消    创建并应用
```

- 接口、凭据、地址因服务商不同而变化；Bedrock/Azure 等必需字段仍在首层，不为追求固定字段数量而隐藏。
- 名称全宽，关联的短字段在空间允许时并排；长地址和长接口名称优先完整显示。
- API 接口影响认证、可用凭据与能力，因此多接口选择不归入高级配置。
- 「开放能力」收起时不暗示模型已获得这些能力；它仅表示连接开放范围。完整模型能力证据留在模型部署中。
- 已选择涉及上游工具或远程联网的能力时，其风险摘要在收起后仍可见；接受控件与完整后果保持绑定。
- 「连接选项」摘要在使用代理、非默认并发或其他特殊配置时反映真实值。
- 编辑时保留已保存值；切换服务商/接口造成重置时反馈具体变化，不能静默丢失操作者的修改。

### 4.3 代理提示的呈现

代理选择后的拟定短摘要：

> 代理可见目标 IP、端口和 TLS 服务器名。Halro 使用系统信任库校验证书。查看信任详情

展开内容保留现有完整语义：不提供证书固定、系统已信任的代理 CA 仍受信任、服务商自行执行的工具或上游联网不经过此连接器。代理身份与端点仍可核对。

另外单独处理明文代理认证、私网/回环访问例外和高风险能力：需要明确接受的后果不得折叠为普通帮助。代理告知条件化，也不能连带移除直连情况下仍然适用的上游联网风险。

| 安全策略 | 策略类型、状态、绑定项目和规则摘要 | 复杂概念用结构化编辑与示例入口承载 | 规则作用范围、拒绝行为、扩大权限及二次认证 |
| 用量与调用 | 时间范围、常用筛选、统计、调用列表 | 低频筛选展开；详情抽屉集中承载错误与原始数据 | 时区、金额单位、partial/stale/unknown、失败原因 |
| 运行治理 | 对象关系、当前状态、成本和下一步 | 常规页与首次接入教学分开；关系与下钻替代长篇概念说明 | Run/Attempt/Outcome 的真实关系、归因和证据缺失 |
| 告警与审计 | 待处理告警、投递结果、审计事件 | 状态优先；签名、Webhook 和审计技术字段放详情 | 投递失败、确认结果、审计完整性和恢复动作 |
| 集群 | 本节点角色、复制状态、异常 | 高级水位和标识进入详情；刷新频率靠近刷新入口 | 本节点视角、只读/不可用、复制落后，不能将其包装成全局健康 |
| 设置及根密钥托管 | 分区、当前值、作用域、生效方式 | 去掉对每个分区的职责复述；标签化作用域 | 重启要求、数据裁剪、MFA、密钥恢复、账户权限 |
| 登录、Setup、首次引导、404 | 当前任务、必要输入和下一步 | 移除品牌说明和原理段落；每步一个明确目标 | 首次建号边界、密码/MFA 要求、错误与恢复入口 |
| 全部 Modal/Drawer/空状态/错误态 | 对象、操作、必要内容、结果 | 统一头部、帮助、页脚与滚动模式 | 焦点、离页保护、危险确认、提交失败和可恢复性 |

本轮以控制台为完整范围；官网与文档站是独立的信息消费场景，不直接套用后台的删文案规则。

## 6. 视觉与组件规格

### 6.1 视觉方向

- **层级**：页面标题、区块标题、字段/数据、辅助内容四个主要层级；减少重复的粗体标题和相互竞争的卡片。
- **颜色**：中性表面承载内容，品牌色集中用于主操作与选中；warning/danger 只用于真实的注意事项与风险。
- **边界**：优先用间距与对齐分组，仅在交互边界、数据分区或滚动容器需要时添加线框；减少卡片套卡片。
- **密度**：删除文字后同步收回空白，避免留下大块空区域；不通过缩字号或降低对比度制造精简。
- **表单**：沿用现有 Token；弹窗先按约 720–800px 的桌面宽度试排，由真实内容决定。小窗口转单列，不强行维持两栏。
- **操作区**：一个视觉主操作；较长表单可保留固定页脚，正文有足够底部空间，聚焦字段与错误不会被遮挡。
- **动效**：短而明确地表达展开、切换和结果；支持减少动画，避免为视觉效果延迟任务。

所有尺寸优先映射现有 Token。新值需要同时验证 Light/Dark、中文/英文、320px 窄屏和缩放。

### 6.2 共享契约改造

| 组件/模式 | 拟定改动 | 必须一起处理 |
| --- | --- | --- |
| `PageHeader` | `eyebrow`、`description` 可选；无内容不占位 | 审核各调用点；首次引导和强制 MFA 等必要上下文不能批量删掉 |
| `Field` | 保留标签、必要短提示和错误；详细帮助与普通 hint 区分 | 保持 `aria-describedby`、错误关联与焦点定位 |
| 折叠配置区 | 统一展开控件、摘要、非默认状态与错误自动展开 | 键盘、`aria-expanded`、关闭后焦点、表单 dirty 状态 |
| 风险告知 | 明确出现条件、简短后果、可展开详情 | 必须接受的告知不变成普通帮助，不改变服务端校验 |
| Modal/Drawer | 统一宽度策略、滚动、操作区和必要状态 | Escape、焦点约束、恢复焦点、提交中保护、离页保护 |
| 资源列表 | 名称、判断所需状态与少量事实优先，详情承载其余内容 | 不删除区分对象所需字段；正常、未知和异常状态可辨识 |
| 通知与反馈 | 同一结果只反馈一次；优先在发生位置说明问题 | 沿用现有 NotificationProvider 契约，持久错误不换成自动消失通知 |

先复用原生语义和已有组件，仅在试点中出现可复用需求时抽取共享能力，不新增另一套 UI 框架。

## 8. 验收标准

### 8.1 精简效果

以下是拟定目标，阶段 0 采集基线后校准，不能为达数字删掉必要信息：

- 全系统通用页头不再强制附带说明段落；例外必须说明它补充了哪项必要上下文。
- 试点普通创建路径中，默认可见的辅助说明文字争取减少约 50%；分别记录真正删除和移入展开区的内容。
- 统计同语言、同视口、同数据和同表单状态下的辅助说明；标签、真实数据、风险告知另列，不混在减量分母中。
- 同一弹窗内不再同时出现相同能力的完整摘要和完整编辑列表。
- 普通创建服务商的必需字段争取在 1440×900、100% 缩放的首屏完成；特殊接口和风险告知可以增加高度。
- 主任务点击数不高于基线；专业设置允许增加一次展开，但不能藏到多个不明确的层级中。

### 8.2 任务与语义

必须验证：

1. 创建普通服务商 → 创建部署 → 创建路由 → 允许项目访问 → 获取密钥并完成接入。
2. 选择代理、配置网络例外、启用涉及上游联网的能力时，相关后果与接受要求仍然清楚。
3. 接口切换、凭据不匹配、能力未知、没有价格、只读等状态不被简化为正常可用。
4. 展开项内出现错误时自动展开、滚动与聚焦；取消、重试、离页保护和返回路径完整。
5. 密钥一次性展示、二次认证、删除/禁用后果和已有安全校验保持有效。
6. 设置保存成功、应用中、应用失败、需要重启等状态准确区分。

### 8.3 视觉与可访问性

- Light/Dark × 中文/英文覆盖全部改动页面；普通数据、长名称、长地址与空/异常数据都有代表性检查。
- 代表场景检查 1440×900、1280×800、820px 边界、390px 和 320px，以及 200%/400% 缩放。
- 键盘可完成任务，展开控件可达，焦点清晰且不被固定区域遮挡；读屏能获知标签、状态与错误。
- 正文对比度不低于 4.5:1，适用的大文字与关键非文字边界不低于 3:1；沿用现有 12px 字号底线与窄屏 44px 交互目标规则。
- 帮助支持键盘与触控；不依赖悬停，不只靠颜色表达状态；局部表格可滚动，页面不横向溢出。

### 8.4 工程验证

遵循根目录 `AGENTS.md`：

- 仅编写方案的阶段不运行应用测试或构建；实施阶段已按后续条目完成验证。
- 实施时，纯文案/视觉调整用聚焦视觉检查；样式和主题变更运行 `web/src/design-system.test.ts`。
- 表单、折叠、焦点、选择联动等行为变更先运行直接相关测试；TypeScript 类型或逻辑变更运行 typecheck。
- 全量前端 gate 在最终交付或推送前执行一次，不为每次小改重复执行。
- `web/` 实现与 `internal/webui/dist` 同步提交；推送前按仓库策略检查生成资源漂移。
- 迭代期间不为纯前端改动反复运行 Go 全套测试；若触及 Go，先验证受影响包。发布代码的推送前按仓库策略运行一次完整 Go gate；纯文档追加不重跑已通过的 gate。
- 真实付费服务商测试需要用户明确要求。日常界面验收使用隔离合成数据。
