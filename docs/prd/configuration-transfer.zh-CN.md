# Halro 配置迁移方案

配置迁移用于在一个新实例上重建源实例的模型拓扑和项目规则。管理员从源实例的「设置 → 配置迁移」下载带版本号的 JSON，在目标实例选择同一文件、绑定目标凭据、预览并确认。配置包 v1 支持最多 1,000 条配置和 2 MiB 文件。

| 配置 | 迁移内容 |
| --- | --- |
| 服务商 | 类型、端点、协议与能力绑定、启用状态和并发设置。需要代理的连接在目标实例重新选择代理。Bedrock Mantle 项目可替换。 |
| 模型部署 | 服务商引用、目标模型、区域、协议、能力、并发及当前生效的计价规则，包含分时规则。目标实例重新解析能力；目录无法证实的能力需要作为人工声明确认。 |
| 模型路由 | 公开模型别名、部署引用、优先级和路由策略。 |
| 安全策略 | 脱敏和 Token Guard 的规则及启用状态。 |
| 项目 | 允许的模型、访问网段、限流、预算上限、治理配置及安全策略引用。 |
| 网关密钥 | 名称、项目、权限范围、启用状态和到期时间。确认时生成目标实例的新密钥，原文只在成功响应中提供一次。 |

凭据记录及其引用、原密钥及哈希、管理员账户、日志、用量、历史账务、探测结果、能力检测记录、历史和未来价格版本、实例级配置均排除。若源端点含查询参数、用户信息或片段，配置包省略该端点，导入时填写目标端点。

目标实例应先完成管理员初始化，并可预先创建测试凭据、代理和配置实例级策略。配置迁移会检查目标不存在待迁移类型的记录，包括已删除的记录，避免合并路由或项目权限。预览验证版本、引用、策略、模型能力、端点与凭据的匹配，以及目标环境的服务商使用条款。正式导入使用预览标识并重新验证，应用时要求管理员重新认证。所有配置和导入审计记录在同一事务提交。失败后可重新预览，成功后重试会被拒绝，已签发的密钥原文无法重放。

部署与路由以停用状态写入。导入结果列出源实例原本启用的部署和路由。操作员先在目标实例测试并启用部署，再启用对应路由。没有有效价格的部署还需先配置价格。项目规则与新密钥随配置激活。

| Admin API | 用途 |
| --- | --- |
| `GET /admin/api/v1/configuration/export` | 下载配置包 JSON。 |
| `POST /admin/api/v1/configuration/import/preview` | 接受 `{bundle, bindings}`，返回记录数量、绑定要求、验证问题、待启用资源和可应用的 `plan_id`。 |
| `POST /admin/api/v1/configuration/import` | 接受相同的 `bundle`、`bindings`、`plan_id` 及 `current_password`，启用 MFA 时带 `totp_code`。成功返回 `201` 和本次签发的网关密钥。 |

`bindings` 以配置包中的服务商 ID 为键，每项包含目标 `credential_id`，可覆盖 `base_url`、`bedrock_project_id` 或选择 `egress_proxy_id`，受限服务商带上目标条款的 `acknowledged_policy_revision`。

验收使用两个独立本地实例。验证文件排除源凭据和原密钥材料，未绑定或引用不完整的导入不会写入，重复提交不会签发新密钥，源密钥无法访问目标网关，并用模拟服务商验证部署和路由可按现有流程恢复。
